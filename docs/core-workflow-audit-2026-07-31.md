# DB Mock 核心工作流审计（2026-07-31）

## 1. 范围与证据

本轮按“接入主机 → 选择数据库模板 → 创建测试数据库 → 跟踪部署任务 → 获取连接信息 →
启停和排障 → 备份或删除”走查管理员与只读角色。代码、自动化测试和本地隔离 PostgreSQL
控制平面用于验证；主机、实例和凭据均为合成数据，没有连接公司网络、真实 SSH 主机或真实数据库。

因此，本轮可以确认页面衔接、默认值、权限、持久化和失败恢复入口，但不能代替首批授权测试主机上的
镜像拉取、Compose 执行、健康检查和数据恢复演练。

## 2. 核心流程基线

| 步骤 | 操作与页面跳转基线 | 重复输入或缺失上下文 | 状态、风险、断点与命令行依赖 |
| --- | --- | --- | --- |
| 接入主机 | 主机页填写连接信息，测试连接后保存；从创建流程缺主机时可原地进入接入并在能力检测后返回 | SSH 地址、账号、端口池等首次必须填写；模板、项目和返回位置可保留 | 指纹、Docker、架构、目录、端口池均有检测结果；失败可在主机上下文恢复。真实网络与 sudo 策略仍需公司试用验证 |
| 选择模板 | 创建抽屉第 1 步；常用版本 1 次选择，其他版本需搜索并选择 | 团队常用版本由全局历史推导，不代表某个项目的标准版本 | 停止新建的版本不会进入常用入口；没有历史时安全回到完整目录 |
| 创建测试数据库 | 基础信息、资源、选项、确认 4 个后续步骤，无页面跳转 | 项目已能复用环境、使用周期和标签，但同一项目每次仍需重新选择模板，并把模板默认 `1/1/10` 改成团队常用 `2/4/20` | 主机按实时余量推荐且提交时复核；这部分不应被固定项目主机替代 |
| 跟踪部署 | 提交后停留在实例详情；可 1 次进入任务记录并返回同一实例 | 无需人工记录任务 ID | 进度、下一步、取消安全点、失败原因和恢复入口持续可见；真实执行时长只在授权主机验证 |
| 获取连接信息 | 成功面板或任务入口进入连接页；授权角色明确揭示后可 1 次复制完整摘要 | 项目、环境、用途、负责人和到期时间已进入摘要，无需另写交付文档 | 只读角色不读取密码；读取失败可原页重试 |
| 启停和排障 | 列表或详情选择操作并确认；批量操作先预览接受与跳过项 | 无需逐项往返详情 | 主机类失败先检查主机再重试；普通失败保留任务和实例上下文 |
| 备份或删除 | 实例详情创建/恢复/删除备份；删除先进入清理审查并输入实例名确认 | 用途、负责人、备份和活动任务已集中显示 | 删除失败保留任务、端口和主机恢复上下文；仍禁止用命令行绕过受管目录边界 |

## 3. 问题分级

### P0

本轮未发现新的阻止本地隔离流程或产生数据、凭据风险的 P0。真实 SSH、镜像、Compose 和备份恢复
仍属于公司试用前必须完成的外部验证，不因本地页面通过而视为已消除风险。

### P1

1. **项目重复部署仍需选择模板并修改三项资源。** 环境、使用周期和标签已经属于项目约定，
   但模板版本与 `CPU / 内存 / 磁盘` 仍重复填写。复制部署可以复用，但要求先找到且保留一条
   配置正确的源实例，不适合作为团队标准配置的唯一载体。
2. **项目入口没有把团队约定延续到模板步骤。** 从项目卡片点击创建后仍停在模板选择，增加一次
   决策和一个容易选错版本的节点。

### P2

1. “常用版本”基于全局部署历史，不区分项目；它适合降低目录搜索成本，但不能表达某个团队的
   固定版本和资源基线。
2. 项目卡片原来只展示生命周期默认值，用户无法在发起创建前确认模板和资源约定。

## 4. 第一实现切片：项目默认模板与资源

### 解决的问题

让同一项目反复创建同一种测试数据库时，不再重复选择版本和修改 CPU、内存、磁盘，同时保留
实时主机调度，避免把今天可用的主机固化成明天的故障点。

### 可观察验收标准

1. 管理员和运维可为项目保存一个仍允许新建的固定模板版本及完整 CPU、内存、磁盘规格；
   服务端拒绝缺项、失效模板和低于模板下限的资源。
2. 项目卡片展示模板、版本和资源摘要；只读角色可查看但不能编辑或发起部署。
3. 从已配置项目发起创建时直接进入基础信息，显示已应用提示；填写名称后资源步骤已是项目规格。
4. 主机保持“自动推荐”，按架构、镜像、实时资源和端口重新计算；项目不保存凭据、主机或端口。
5. 模板删除或停止新建时不使用失效引用，安全回到模板选择并提供刷新或改选路径。
6. 中英文、1440px 和 1024px 页面无重复标题、悬空按钮、遮挡、横向溢出或控制台错误。
7. 项目配置保存、清除、下限验证、审计变化、创建预填和只读权限有自动化或真实页面证据。

### 预期价值

从项目入口发起的常用部署减少 1 次模板选择、3 项资源修改和 1 个向导步骤；目标主机仍使用实时
推荐，因此减少重复输入的同时不牺牲容量与故障切换安全性。

## 5. 本轮验证结果

- 后端集成测试覆盖配置创建、列表读取、清除、模板最低资源、停止新建模板及模板删除级联；
  项目审计单元测试覆盖模板和三项资源变化。
- 前端单元测试覆盖生命周期默认值与完整部署配置转换；现有端到端规格增加项目卡片、编辑回显、
  从项目创建跳步、资源预填、动态主机和只读角色断言。
- `npm run typecheck`、188 个前端单元测试和 `npm run build` 通过；端到端规格另外通过 TypeScript
  编译检查。
- 使用合成项目、PostgreSQL 17、三台合成主机和管理员/只读账号在运行页面完成真实交互。
  1440×1000 与 1024×900 下抽查项目列表、编辑弹窗、创建基础信息和资源步骤；没有悬空按钮、
  重复标题、遮挡、横向溢出或控制台错误，中英文均可读。
- 使用隔离 PostgreSQL 执行 `go test ./...` 通过。全量检查同时发现并修正一个既有批量清理测试
  未初始化任务管理器的夹具问题；生产逻辑未因此改变。

## 6. 后续验证重点

完成本切片后，下一轮优先用一台明确授权的可回收测试主机验证真实部署耗时、镜像失败、健康检查
失败与重试闭环；若外部环境尚未授权，则继续审计现有失败恢复信息中仍需人工查日志的最高频断点。
