# DB Mock MVP 最终验收（2026-08-04）

## 1. 结论与边界

当前版本已经在一次性本地环境完成唯一核心闭环，可以进入公司专用测试主机的受控日常试用：

`初始化 → 接入真实 SSH/Docker 主机 → PostgreSQL 17 创建 → 任务跟踪 → SQL/连接交付 → 日志 → 停止 → 启动 → 重启 → 安全删除`

验收没有连接公司网络或真实主机，没有使用真实业务数据、账号、密码或 SSH 私钥。目标主机是带
OpenSSH、Docker CLI/Compose 且挂载本机 Docker Socket 的一次性 Alpine 容器；它覆盖真实 SSH 命令、
Compose、容器、端口、数据目录和 PostgreSQL 进程，但不替代公司防火墙、代理、DNS、磁盘与权限策略验证。

## 2. 可重复真实生命周期

新增 `frontend/tests/e2e/real-lifecycle.spec.ts`。该用例默认跳过，只有显式设置
`DBMOCK_REAL_LIFECYCLE=1` 并提供可丢弃 SSH 密码时运行；凭据只从环境变量读取，不写入测试产物或仓库。

本轮在空 PostgreSQL 17 元数据库和空目标目录中验证：

1. 首次页面创建单一管理员并进入只有四个一级入口的工作台。
2. 页面填写 SSH 密码、连接地址、数据根目录与 `25520–25529` 端口池，真实探测主机指纹、架构、
   Docker、Compose、CPU、内存、磁盘、目录和端口后保存；异步探测收敛为 online。
3. 从数据库页搜索并选择内置 PostgreSQL 17，以默认 `1 CPU / 1 GiB / 10 GiB` 创建数据库；创建任务
   完成且实例收敛为 running。
4. 页面显示地址、端口、账号、密码、数据库、URI 和 JDBC；使用相同交付凭据从独立
   `postgres:17-alpine` 客户端执行 `SELECT 1`，返回 `1`。
5. 日志页读取真实 PostgreSQL 日志；页面依次提交停止、启动和重启，三个持久化任务均成功，状态分别
   收敛为 stopped、running、running。
6. 输入精确数据库名称提交删除；删除任务成功，任务页保留回执。外部核对确认没有带
   `dbmock.instance` 标签的容器、没有 `25520` 端口映射、实例目录已移除，只保留空的受管父目录。

最终无 Mock 用例用时约 25 秒（镜像已在本机缓存）。运行时收集的控制台错误和意外 4xx/5xx 均为空。
1440px 与 1024px 的真实运行详情页没有悬空按钮、重复标题、遮挡或页面级横向溢出，连接交付、停止、
重启和删除主操作均保持可见。

## 3. 干净在线安装

使用当前 `deploy/docker/Dockerfile` 构建当前检出版本，再以当前 `deploy/compose.yaml` 和独立 Compose
项目名从空网络、空 `postgres_data`、空 `dbmock_data` 启动：

- `postgres:17-alpine` 达到 healthy；
- 当前检出版本的 DB Mock 镜像达到 healthy；
- `/api/v1/health` 返回 `database=true`、`status=healthy`；
- `/api/v1/setup/status` 返回 `initialized=false`；
- 端口只绑定本次指定的 `127.0.0.1:18095`；普通停止不需要删除卷。

容器内当前前端还通过了 4 条稳定 UI E2E，覆盖初始化/登录、四入口导航、主机、最小创建、任务、连接
交付、日志、生命周期和安全删除，并检查 1440px/1024px 的页面级溢出和浏览器运行时错误。公司首次试用
仍必须在实际网络执行 `./scripts/install.sh`，把镜像首拉、代理与带宽作为准入项。

## 4. 范围与安全回归

- 后端公开业务路由只剩初始化/个人账号、工作台、主机、内置模板、数据库、核心任务和只读设置。
- task worker 只注册 `host.probe`、数据库创建/启动/停止/重启/删除和历史备份精确删除。
- 批量生命周期、主机 Docker 管理、备份创建/恢复/调度、升级、改配、镜像/仓库/上传、项目/用户治理、
  告警/Webhook/指标均无当前执行入口；旧 queued 任务有保守终止策略。
- 历史表、字段、任务和备份记录不做破坏性迁移；历史备份仍能在数据库删除弹窗内精确名称删除。
- PostgreSQL 17 后端全量测试、前端 TypeScript、36 个文件共 152 项单测、生产构建、4 条稳定 UI E2E
  和 1 条真实 SSH 生命周期均通过。
- 仓库中没有 `.env`、真实凭据、私钥、真实公司数据或生成测试报告。

## 5. 公司试用入口与停止条件

公司试用按 [`internal-trial-checklist.md`](internal-trial-checklist.md) 执行，首先只选择一台可丢弃测试主机
和 PostgreSQL 17。重点记录首次镜像拉取、创建、故障恢复与删除耗时，以及公司网络/权限差异。

出现以下任一情况立即停止：删除范围无法证明、凭据泄露、重复创建、任务与实际容器状态持续不一致、
必须手工改元数据库才能继续，或目标主机只能通过放宽公司安全策略接入。回滚时先停止新任务并等待终态，
使用 `make down` 保留控制平面卷；禁止未经确认执行 `down -v`。
