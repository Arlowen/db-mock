# DB Mock MVP 需求规格

状态：当前范围权威

更新时间：2026-08-04

## 1. 产品目标

DB Mock 服务于一名具备数据库、Docker 和服务器基础知识的管理员，减少测试数据库部署、
连接信息交付、日常启停、排障和清理中的重复命令与人工记录。

唯一核心闭环是：

1. 初始化并登录。
2. 接入并验证一台预装 Docker 的 SSH 主机。
3. 选择内置数据库及固定版本。
4. 使用最少必要配置创建测试数据库。
5. 观察异步任务的阶段、进度、日志和错误。
6. 复制完整连接信息交给开发人员。
7. 启动、停止或重启数据库。
8. 查看当前状态和最近容器日志。
9. 输入数据库名称确认并安全删除。

不能直接缩短、支撑或保护这条闭环的能力，不属于当前 MVP。

## 2. 使用假设与边界

- 首版只有一个管理员账号；不提供用户管理和角色治理界面。
- 数据库只用于开发和测试，不管理生产数据库。
- 目标主机是可通过 SSH 直连的 Linux 或 macOS 主机，且已经安装 Docker Engine 与
  Docker Compose v2。
- 优先联网拉取模板声明的公开容器镜像。
- 一个数据库只部署在一台主机，复杂集群和跨主机高可用不在范围内。
- 平台不登记已有数据库连接，不提供 SQL 控制台、表浏览、数据编辑或数据库内部账号管理。
- 平台不自动修改防火墙、云安全组、Docker 安装或操作系统软件源。

## 3. MVP 信息架构

登录后只显示四个一级入口：

1. 工作台
2. 主机
3. 数据库
4. 任务

模板选择位于“创建数据库”流程内。个人资料、语言、修改自己的密码和退出位于右上角个人菜单。

工作台只展示：

- 可用主机数与主机总数；
- 数据库总数与异常数据库数；
- 执行中任务数与待处理失败任务数；
- 待处理异常及其资源、原因和恢复入口；
- 明显的“创建数据库”按钮。

## 4. 功能需求

### 4.1 初始化、登录和账号安全

- 未初始化时只能创建第一个管理员账号，成功后关闭公开初始化。
- 管理员可以登录、退出、修改昵称、界面语言和自己的密码。
- 修改密码必须校验当前密码；密码使用 Argon2id 哈希保存。
- 会话 Cookie 使用 HttpOnly、SameSite；浏览器公开地址为 HTTPS 时同时使用 Secure 和 HSTS。
- 任意 API 返回 `401` 时，前端立即卸载已登录页面并返回登录页。
- MVP 不提供创建其他账号、禁用账号、重置他人密码或修改角色的入口。

### 4.2 主机管理

- 可以添加、编辑、重新检测和删除主机。
- 接入字段只包含名称、SSH 地址/端口/用户、密码或私钥、可选数据库连接地址、数据根目录和端口池。
- 默认 SSH 端口为 `22`，数据根目录为 `/opt/dbmock`，端口池为 `20000–40000`。
- 保存前必须由服务端验证 SSH、主机指纹、操作系统与架构、Docker、Compose、CPU、内存、
  磁盘、数据目录可写性和端口池可探测性。
- 验证结果签发短期且绑定连接参数的验证令牌；新增主机或修改关键连接参数时必须提交有效令牌。
- 首次连接显示主机指纹供确认；已保存主机的指纹变化必须阻止后续操作。
- 主机列表和详情清楚展示在线、离线、不可用原因、最近检测时间和当前容量。
- Docker 或 Compose 缺失时，只提示在目标主机修复后重新检测，不提供自动安装或升级。
- 主机仍有托管数据库、活动操作或删除证据无法读取时，删除保持禁用。

### 4.3 内置数据库模板

- 创建流程只展示代码内置且标记为 `standard` 的单机模板和固定版本。
- 实验模板和历史自定义模板不得出现在新建选项中；已有实例仍需能显示模板和执行核心生命周期。
- 模板声明镜像、支持架构、默认端口、最低 CPU/内存/磁盘、认证方式、连接协议、数据目录、
  健康检查和必要初始化参数。
- 新模板或新版本通过代码、测试和版本发布加入，不提供上传 UI。
- PostgreSQL 17 是 MVP 干净环境和公司试用的首要验收模板；其他内置模板只有通过镜像与关键流程
  检查后才应作为已验证模板交付。

### 4.4 创建数据库

创建流程固定为三步：

1. “数据库与名称”：选择内置模板/固定版本并填写唯一部署名称。
2. “资源与主机”：使用模板默认或预设资源，必要时调整 CPU、内存、磁盘，选择或自动推荐主机，
   填写模板声明的必要初始化参数。
3. “确认”：核对数据库、版本、主机、资源、认证方式和公开镜像后创建。

前端提交体只包含名称、模板版本、可选主机、CPU、内存、磁盘和模板参数。端口、绑定地址、
数据库用户名、数据库名、密码和未显示的兼容字段由服务端根据模板与当前主机安全推导。

- 名称重复、资源不足、架构不兼容、主机不可用、端口冲突或活动操作必须在入队前拒绝。
- 创建成功后直接进入数据库详情，并关联创建任务。
- 创建请求明确失败时保留草稿和原因；网络结果不确定时先刷新实例与任务证据，禁止直接重复提交。

### 4.5 数据库列表与详情

- 列表展示名称、模板/版本、核心状态、主机、资源和直接可见的日常操作。
- 支持按名称搜索，按主机和核心状态筛选；不展示项目、环境、标签、到期、批量选择或复制部署。
- 详情只包含“概览 / 连接信息 / 日志”三个标签。
- 概览展示当前状态、模板版本、主机、端口映射、资源、创建时间和健康状态。
- 列表与详情都可执行单个数据库的启动、停止和重启；提交前说明当前状态及连接中断影响。
- 不提供监控图表、常规备份管理、升级、在线改配或更多操作菜单。

### 4.6 连接信息交付

- 运行可交付的数据库可查看地址、端口、用户名、适用时的密码、数据库名、URI 和 JDBC。
- 支持复制单个字段以及一次复制完整连接摘要。
- 读取明文凭据前显示敏感信息和剪贴板风险提示；离开连接标签后清除前端明文状态。
- 没有密码认证的模板不得生成或展示虚假密码。
- 连接信息读取失败不能改变数据库状态；页面提供原地重试和控制服务排查建议。

### 4.7 状态、日志和日常操作

- 至少区分创建中、运行、已停止、启动中、停止中、重启中、删除中、失败和异常状态。
- 启动、停止、重启均创建持久化异步任务；取消确认不得创建任务。
- 详情日志支持最近 100/500/1000/5000 行、手动刷新、可选自动刷新和下载。
- 日志加载中、空、失败与重试状态必须明确；日志内容不得渲染为 HTML。
- 操作请求未入队或结果不确定时，页面保留当前资源上下文并禁止盲目重复提交。

### 4.8 安全删除

- 删除前从服务端读取数据库最新状态、活动任务和历史托管备份证据。
- 活动任务、不可删除状态、证据读取失败或历史备份存在时，不允许提交数据库删除。
- 因旧版本产生的托管备份可在同一删除流程逐项输入备份名称删除；MVP 不提供创建或恢复备份入口。
- 所有阻断解除后，用户必须输入准确数据库名称才能永久删除。
- 删除任务只清理平台拥有的 Compose 项目和受管数据目录；不得对未解析、外部或宽泛路径递归删除。
- 删除入队后直接打开任务；结果不确定时清空确认名称并锁定重复提交，刷新证据后才能继续。

### 4.9 任务反馈与安全重试

- 创建、启动、停止、重启和删除使用持久化任务，应用重启后能恢复排队任务，并把无法继续的任务
  标记为中断。
- 任务列表和详情展示类型、资源、状态、阶段、进度、时间、日志、错误原因、影响和下一步。
- 失败任务可以回到对应数据库；主机类故障可以打开对应主机并保留原任务上下文。
- 只有失败类型可重试、资源仍匹配、没有活动冲突且证据完整时才开放重试。
- 重试请求被拒绝时明确“未创建新任务”；响应不确定时查找同一操作链的后继任务，证据不足时
  持续禁止再次提交。
- 任务成功不等于数据库已经健康；创建或启动完成后仍应等待健康状态收敛再交付连接信息。

### 4.10 最小在线部署

- 一个 Go 应用容器同时提供 API 与内嵌 React 页面，另使用 PostgreSQL 保存元数据。
- 提供一种 Docker Compose 在线安装方式、可提交的 `.env.example`、健康检查、升级脚本和排障说明。
- PostgreSQL 数据和应用主密钥使用命名卷持久化；普通 `docker compose down` 不删除数据卷。
- 部署变量严格校验；无效公开 URL、时长、任务并发、TLS 配置或可信代理配置必须阻止启动并指出变量。
- 控制平台最低配置为 2 CPU、4 GiB 内存和 20 GiB 可用磁盘。

## 5. 安全与数据保护

- SSH 凭据和数据库凭据由 32 字节主密钥使用认证加密保存；密钥位于应用数据卷或显式配置文件。
- API 不在实例、任务或日志响应中携带明文密码；连接信息使用受保护的独立读取接口。
- 服务端仍是所有写权限、状态转换、资源校验和删除边界，隐藏前端入口不能替代后端校验。
- 任务和请求日志不得主动写入密码、私钥、Token 或完整凭据 URI；通用错误落盘前至少遮蔽
  `password`、`token`、`secret` 和私钥等稳定标记，结构化变更继续递归遮蔽敏感键。
- SSH 命令参数、Compose 项目名和受管路径必须由已校验数据生成，不执行任意用户 Shell。
- 不提交 `.env`、密码、SSH 私钥、TLS 私钥、真实主机地址或公司数据。

## 6. 明确移出 MVP

- 项目、环境、标签和复杂资源组织；
- 多用户、管理员/运维/只读角色体系和用户管理；
- 告警中心、Webhook、审计查询/CSV、历史监控图表；
- 批量启停、批量清理、到期治理和长期保留；
- 自动或手动备份、恢复和控制平面备份恢复 UI；
- 数据库版本升级、运行配置在线调整和复制部署；
- 私有仓库、离线镜像上传/分发/清理和完全离线安装包；
- 自定义模板上传和实验性多容器数据库；
- 自动安装/升级 Docker、代理配置和维护策略；
- SQL 控制台、数据浏览/编辑、数据库账号管理；
- SSO、LDAP、公开 API Token、多主机集群和生产高可用。

## 7. 底层兼容边界

当前数据库迁移、历史实例和旧任务仍引用部分非 MVP 字段、表、API 和后台 worker。删除顺序必须是：

1. 先停止新 UI 流程和新数据写入。
2. 证明核心流程、历史实例读取、任务恢复和升级库不再依赖。
3. 关闭对应路由或 worker，并补充兼容响应。
4. 最后删除无用服务代码；默认不删除历史表或执行破坏性迁移。

兼容代码的存在不构成产品入口或功能承诺。

## 8. 验收标准

- [ ] 一级导航只有工作台、主机、数据库和任务。
- [ ] 干净环境可以完成首次管理员初始化、登录、退出和修改自己的密码。
- [ ] 可以使用密码或私钥接入并验证一台预装 Docker/Compose 的主机。
- [ ] 主机不可用原因清楚，仍有数据库时不能删除。
- [ ] 可以从数据库页直接选择内置 PostgreSQL 17 并用三步最小表单创建。
- [ ] 可以观察创建任务的阶段、进度、日志、失败原因和下一步。
- [ ] 创建成功后可以复制所有有效连接字段和完整交付摘要。
- [ ] 可以启动、停止、重启数据库并获得安全反馈。
- [ ] 可以查看当前状态和最近容器日志。
- [ ] 可以输入数据库名称安全删除，活动任务和历史备份会阻断误删。
- [ ] 重复点击或网络结果不确定不会创建重复任务。
- [ ] 非 MVP 功能不出现在导航、主要流程、README、需求和试用清单中。
- [ ] 1440px 与 1024px 的核心列表、详情和弹窗无页面级横向溢出或被遮挡主操作。
- [ ] 前端类型检查、单元测试、生产构建、核心 Chromium E2E 和 `go test ./...` 通过。
- [ ] 可以按照部署文档在干净在线环境启动 Compose、通过健康检查并完成核心闭环。
- [ ] 仓库没有密码、私钥、`.env`、测试报告或真实公司数据。
