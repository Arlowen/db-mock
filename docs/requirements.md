# DB Mock 需求规格

状态：已确认，可进入实现  
更新时间：2026-07-22

## 1. 产品目标

DB Mock 面向个人及公司内部团队。用户在 Web 页面上选择数据库类型、版本和目标
主机，平台通过 SSH 在目标主机上生成并执行 Docker Compose 项目，完成数据库实例
的完整生命周期管理。

平台只部署拥有可用容器镜像的数据库，不登记或代理既有数据库连接，也不提供 SQL
控制台、表浏览、数据编辑或数据库内部账号管理。

## 2. 首版范围

### 2.1 支持

- Linux：Ubuntu、Debian、Rocky Linux、AlmaLinux，`amd64` 与 `arm64`。
- macOS：必须预装且运行 Docker Desktop，并开启 Remote Login/SSH。
- IPv4；不要求 IPv6。
- 最多 10 台主机、30 名用户、50 个数据库实例。
- 单机实例；一个实例只属于一台主机。复杂数据库允许在同一主机内运行多个容器。
- SSH 直连，不支持跳板机。
- SSH 密码和私钥认证，首次连接确认并保存主机指纹。
- Linux 可选择由平台安装/升级 Docker；此时 SSH 用户必须具备免密 `sudo`。
- HTTP/HTTPS 代理、私有仓库凭据和私有仓库自签名 CA。
- 平台默认 HTTP；配置证书后由同一个 Go 服务直接提供 HTTPS，也允许由受控反向代理终止 TLS。

### 2.2 不支持

- Windows。
- 跨主机数据库集群、故障数据迁移和自动主从切换。
- 跨主机备份、对象存储和备份下载。
- SQL 控制台、表结构/数据浏览与数据库内部账号管理。
- LDAP、AD、OIDC、SSO 和项目级细粒度权限。
- 面向第三方自动化的稳定公开 API 与长期 API Token。
- 自动修改操作系统防火墙或云厂商安全组。

## 3. 用户与安全

- 第一次启动进入初始化页面创建首个管理员账号，关闭公开注册。
- 账号分为管理员、运维和只读三种全局角色。管理员可管理账号、系统设置及全部资源；
  运维可管理数据库资源、任务、告警和 Webhook，并可读取审计与数据库连接凭据；只读
  只能查看非敏感资源状态、日志、指标、任务和告警。
- 用户管理、系统设置和审计清理仅限管理员；审计查询与导出限管理员和运维。角色权限
  由服务端校验，页面隐藏无权入口不能替代后端授权。
- 新账号默认只读；升级前已存在的账号迁移为管理员以保持原有访问能力。
- 不能禁用或降级最后一个可用管理员，也不能修改当前登录账号自己的角色。禁用、密码
  重置或角色变更会按策略立即撤销相关会话。
- 所有角色都可修改自己的显示名称和语言偏好。修改自己的密码必须校验当前密码，成功后
  保留发起操作的当前会话并立即撤销该账号在其他设备上的会话；并发密码修改不能相互覆盖。
- 不设置密码长度、复杂度和失败锁定策略；密码仍必须非空并使用 Argon2id 哈希保存。
- 登录会话默认有效 30 天，Cookie 使用 HttpOnly、SameSite 和 Secure（浏览器公开地址为
  HTTPS 时，不依赖 TLS 在应用还是反向代理处终止），并向 HTTPS 页面发送 HSTS。
- 会话因账号禁用、角色变更、密码重置或过期而失效后，页面在任意后续 API 请求收到
  `401` 时立即清除本地认证状态、卸载包含敏感信息的资源页面并返回登录页，不要求用户刷新。
- 默认忽略客户端提交的转发来源头；只有直接连接方命中显式配置的可信代理 IP/CIDR 时，
  才从右向左解析 `X-Forwarded-For`，供会话、审计和请求日志统一使用。
- SSH、镜像仓库和数据库凭据使用平台主密钥加密保存。
- 自定义 Compose 与脚本被视为可信代码。平台展示危险能力风险报告但允许使用
  `privileged`、宿主机挂载和 host 网络等配置，所有执行均写审计日志。
- 审计日志默认永久保留，可检索、导出 CSV 和按时间范围手动清理；清理动作本身保留。

## 4. 项目与资源组织

- 实例可属于一个项目，并选择开发、测试、预发布或生产环境。
- 支持任意标签；项目、环境和标签只用于筛选、统计及 Webhook，不提供项目级权限隔离。
- 项目可选保存新建数据库的默认环境、使用周期和标签。未配置的字段继续使用平台默认值；
  默认值只预填创建表单，不改变权限或模板约束，且可在单次部署中覆盖。
- 项目列表向管理员和运维提供直接创建数据库入口；入口保留项目上下文并应用该项目的部署默认值。
- 项目中仍有主机或实例时禁止删除。
- 主机同时保存 SSH 管理地址与数据库连接地址。
- 实例内部标识和模板版本不可变；显示名称、项目、环境与标签可以修改。

## 5. 主机管理

接入主机时填写名称、SSH 地址/端口/用户、认证方式、数据库连接地址、数据根目录、
端口池、代理及是否允许管理 Docker。平台检测：

- SSH 与主机指纹。
- 操作系统、CPU 架构、CPU、内存、磁盘。
- Docker Engine 与 Compose v2 版本及 Docker 可用资源。
- 数据根目录可写性和端口池。

连接测试成功后由服务端签发 10 分钟有效的验证凭证，凭证绑定 SSH 地址、端口、用户、
认证凭据、数据根目录、端口池和实际主机指纹。新增主机以及修改这些运行参数时必须提交
匹配的验证凭证，不能只由前端声明“已经测试”。已接入主机发生指纹变化时拒绝连接。
探测会实际创建并删除权限为当前 SSH 用户的临时文件以确认数据根目录可写，并使用
`ss`、`lsof` 或 `netstat` 查找端口池中的首个空闲端口。

默认端口池为 `20000-40000`。默认数据根目录由操作系统决定并允许修改。平台只管理
该目录下由自身创建的实例，不接管已有容器。

无法访问软件源的离线 Linux 主机必须预装 Docker。Docker 安装/升级必须由用户手动
触发，不做无人值守自动升级。

主机有未删除实例或平台仍需管理的数据时禁止删除；实例完成安全删除后必须允许移除主机，
不能由保留的实例或任务历史阻断清理。SSH 不可达时只标记离线，不删除记录。
维护模式暂停该主机的主动检测和告警。
主机仍有实例或备份时禁止修改数据根目录；缩小端口池时必须继续覆盖全部现有实例端口。

## 6. 资源调度

- 创建实例时根据架构兼容性、模板最低要求和主机实时剩余资源自动推荐主机，允许
  用户手动选择。
- 资源和端口确定后在同一步展示目标主机；每个架构兼容候选必须标明部署后余量，容量不足、
  端口越界或端口已占用的主机保持可见但不可选择，并说明具体约束。用户不应返回基础信息步骤
  才能改选主机。
- 默认保留主机 10% CPU、20% 内存和 20% 磁盘。
- 支持按数据库模板定义小型、中型、大型资源预设，也支持自定义 CPU、内存和预留磁盘。
- 资源不足或端口冲突时拒绝创建。
- 磁盘容量用于调度与告警，不跨操作系统强制磁盘配额；80% 警告，90% 严重告警。

## 7. 数据库实例生命周期

创建向导：

1. 选择模板和固定版本。
2. 填写显示名称、项目、环境、标签、用途、负责人和预计到期时间；负责人默认取当前账号，
   预计到期默认 7 天，允许改为
   1/3/7/14/30 天或长期保留。
3. 选择资源预设或自定义资源和端口；在同一步查看所有兼容主机的当前可承载结果，并自动推荐
   或手动选择主机。
4. 填写数据库初始化参数、高级环境变量和镜像来源，并设置异常自动重启。
5. 检查变更计划并创建，停留在实例详情查看实时阶段、进度和下一步；进入任务中心查看部署记录时
   保留同一实例的继续入口。

普通创建在模板选择步骤展示最多 3 个团队常用固定版本，按历史部署次数、最近部署时间排序；
已删除实例仍计入使用历史，已停止新建的版本不展示。用户可一键选中并继续检查架构、镜像和主机兼容性，
也可使用原有搜索选择完整目录；没有历史时不展示额外空状态。该排序不存储个人收藏，也不改变服务端权限、
模板可用性或最终调度校验。

从已选模板进入创建流程但没有兼容在线主机时，页面把模板、项目、复制来源和离线镜像选择作为
受限的创建上下文带到主机接入流程。主机能力任务成功后可直接继续创建，并自动选中刚接入的主机；
用户回到主机列表时，页面必须先按模板版本和有效离线镜像计算所需架构，再判断是否可以继续，
不能把任意在线主机标记为可用。只有兼容在线主机存在时才出现继续创建入口；在线主机均不兼容时，
页面明确展示数据库、版本和所需架构并直接提供接入兼容主机入口。接入流程检测到的主机架构不满足
当前数据库要求时不得保存为此次流程的完成结果，避免能力任务结束后再次跳回接入页。目标主机离线、
维护或架构不兼容时不得静默沿用，应提示改选或继续接入。最终提交仍重新校验权限、主机状态、架构、
容量和端口，页面上下文不能绕过服务端约束。

用途、负责人和预计到期时间属于可变管理元数据，不影响数据库容器配置，可在实例详情直接修改。
普通创建选择项目时应用该项目的环境、使用周期和标签默认值；切换项目会重新应用目标项目约定。
复制部署优先保留源实例配置，只有用户明确操作时才改用项目默认值，避免静默覆盖复制内容。
预计到期只用于提醒和人工确认后的清理，不会自动停止、删除实例或备份。工作台展示可用主机、
运行实例、进行中任务、未处理告警、仍待恢复的失败或中断任务、异常实例，以及已到期和未来
7 天内到期的实例。待处理事项只聚合每个现存资源的最新任务；后续已经排队、运行或成功的任务，
以及已删除资源的历史失败，不再制造日常噪声。每项展示可理解的原因、下一步、目标主机，并向
管理员和运维提供任务详情、资源详情和重试入口；只读角色只能查看。到期队列按最早时间排序并在
同一列表集中展示用途、负责人、托管备份数量、活动任务、状态阻断和删除复核就绪状态，可筛选
“可复核”或“有阻断”的候选；只读角色也能查看这些非敏感审查证据。管理员和运维可直接发起
逐实例清理审查、批量延期 7 天、批量改为长期保留，或进入实例详情。批量决定提交前必须逐项预览
原到期时间与新结果，明确数据库运行、数据、备份和连接信息不受影响；服务端限制 1–100 个唯一实例，
每项独立更新并返回成功或结构化拒绝结果，一个实例因并发删除或不存在被拒绝时不回滚其他成功项，
页面汇总逐项结果并允许只重试失败项。只读角色不显示选择和批量决定入口，服务端仍强制校验运维权限。
清理审查必须显示用途、负责人、到期时间、实例状态、托管备份
数量和进行中的操作；存在备份、活动任务或不可删除状态时不得进入永久删除确认，并提供进入备份
或任务页的恢复入口。从清理审查进入备份页时必须保留清理上下文：备份或活动任务清单未知时
不得推断为已具备删除条件，删除任务执行中持续提示等待，最后一份备份删除后可在原页重新执行服务端清理审查；
删除任务失败时必须在清理引导中关联对应备份和任务，展示可理解的原因、影响和恢复建议，并提供任务详情、
主机恢复或安全重试入口；主机恢复完成后返回同一清理上下文。只读角色只能查看阻断条件和恢复信息。
管理员和运维仍可从单项审查中延期 7 天或改为长期保留；永久删除不进入批量决定接口，仍须逐实例输入
精确名称，且服务端在入队事务持有实例行锁后再次检查备份，避免预检后新增备份的竞态。复制部署
复用用途，但负责人重新取当前账号、到期时间重新默认 7 天，避免沿用源实例的旧交付责任和清理时间。

管理员和运维可以从实例列表或详情发起“复制部署”，在创建向导中复用源实例的固定模板版本、
项目、环境、标签、资源、数据库初始化参数、模板参数、镜像来源、额外环境变量和异常自动重启
策略。为避免名称、凭据和调度冲突，新实例名称、数据库密码、目标主机和宿主机端口始终留空或
重新自动选择。进入向导时重新校验源实例、模板版本、项目和镜像来源；来源已删除或模板停止新建
时详情入口禁用，直接 URL 仍明确提示并安全降级为普通创建。只读角色不显示复制入口，服务端仍
强制校验创建权限。复制仅复用部署配置，不复制数据库数据，提交后仍使用标准的
容量、端口、权限、任务和审计链路。

实例支持创建、启动、停止、重启、查看连接信息、日志和监控、修改可变配置、升级和
删除。可变运行配置包括 CPU、内存、预留磁盘、额外环境变量和异常自动重启策略：变更以持久化任务执行，
入队时原子预留目标容量，运行中实例短暂重建容器，已停止实例只校验 Compose 而不启动；
已停止实例下一次启动时使用 `docker compose up` 应用已经校验的配置。执行失败时恢复原
Compose、资源配置、重启策略和运行/停止状态。数据目录、端口、初始化参数和
数据库凭据不随运行配置变更。模板不可变版本必须声明 `password`、`username` 或 `none` 认证方式；
未声明的旧版本按内置模板兼容规则解析，其他模板默认为 `password`。只有 `password` 模式自动生成或接受
自定义密码、加密保存并允许再次查看；其他模式不得生成、保存或交付并未被数据库使用的密码。连接信息按实际
认证方式包含地址、端口、适用的用户名和密码、URI 及适用时的 JDBC 地址，并对无密码认证明确提示受控网络、
防火墙和访问范围要求。管理员和运维揭示连接信息后，可以一次复制包含实例、模板版本、环境、运行状态、认证
方式及全部有效连接字段的交付摘要，直接发送给数据库使用方；环境变量片段也只包含实际存在的字段。连接信息读取
失败时不得只依赖瞬时提示：连接页持续展示错误、说明数据库运行状态不受本次读取失败影响并提供原地重试；
已经展示的凭据在刷新失败时继续保留，但必须明确标注本次刷新未完成。

启动、停止或重启请求如果在任务创建前因状态变化、活动任务、权限或控制服务暂时不可用而被拒绝，
实例详情不得只显示瞬时通知。页面持续说明未创建任务、实例不会因这次请求发生状态变更，并展示
可理解的原因和恢复建议；用户可原地刷新状态、打开实例日志，并且只在刷新后的状态仍允许同一操作时
重试。请求成功入队后该提示自动消失，后续进度和执行失败继续使用标准任务恢复链路。

管理员和运维可在实例列表选择多个实例并批量启动、停止或重启；只读角色不显示选择和操作入口，服务端
仍强制校验运维权限。批量启动只包含已停止实例，批量停止和重启只包含运行中或异常实例，失败实例必须
进入单实例恢复流程，其他状态在确认页明确列出并安全跳过。每个符合条件的实例独立、原子地创建
生命周期任务和审计记录，一个实例因状态变化或活动任务被拒绝不回滚其他已排队项；响应必须逐项
返回已接受和未接受结果。页面以一次聚合请求持续跟踪本次已接受任务到成功或失败，逐实例展示状态、
失败原因、影响和恢复建议；主机故障进入带原任务上下文的主机恢复，其他失败可原地重试，暂时性未排队项
也可单独重试。任务中心保留完整历史入口。单行快捷启停留在列表并刷新状态，不再强制跳转详情页。

异常自动重启支持主机默认值和实例级开关，默认开启。开关通过运行配置任务同步到 Compose
重启策略并由控制面监控共同执行；手动停止的实例不得自动拉起。异常连续重启失败 3 次后
停止重试并告警。

数据库补丁或同主版本升级允许创建内部临时数据快照，失败时回滚，成功后立即删除。
主版本升级首版不支持，除非模板包含经过验证的专属迁移流程。
升级时可为目标版本重新选择直接拉取、匹配的私有仓库凭据或包含目标镜像且与实例主机
架构兼容的离线镜像；成功后实例记住新的镜像来源，失败回滚时保留原来源。

实例支持手动冷备份、恢复和删除。备份保存在实例主机 `<data-root>/backups/`
下，不会在控制节点保留第二份。运行中实例会短暂停机以创建一致归档，完成后恢复
原期望状态。平台记录归档大小和 SHA-256；恢复前重新校验，并创建临时回滚快照。
恢复后容器无法通过健康检查时自动恢复操作前数据。为避免跨数据库版本损坏，备份只能恢复到
原实例且实例必须仍使用备份时的模板版本。平台使用主机上已存在的实例镜像，以禁网、根文件
系统只读的临时容器访问由数据库 UID 持有的数据，不在备份流程中拉取额外镜像。
恢复任务失败、取消或中断时必须把自动回滚结果作为任务结果持久化，至少区分“已恢复操作前
数据”和“回滚未完成”，并记录收敛后的实例状态。实例页和任务详情必须明确说明目标备份是否
生效、当前数据状态和可交付性；绿色运行状态不能掩盖目标备份未生效。管理员和运维可在回滚
已确认后原地重试，只读角色只能查看任务、日志和交付限制。旧任务可使用实例的稳定状态消息
兼容判断，但缺少权威证据时不得猜测回滚成功。
恢复成功时任务结果必须持久化目标备份 ID、名称、备份时间、归档校验值、恢复后健康验证时间
和收敛状态。实例页、任务详情和连接信息页必须使用同一份结果说明当前数据版本；最近一次恢复
结论不能被后续不改变数据的启停或重启操作静默覆盖。实例处于运行中且恢复验证通过后，管理员
和运维可直接显示连接信息，复制的交付摘要必须包含数据版本、备份时间和恢复验证时间；只读
角色可核对恢复证据但不能查看凭据。历史成功任务可使用任务中的备份 ID、完成时间和仍存在的
备份记录兼容展示，缺失的证据必须明确标注而不能虚构。

每个实例可配置每日或每周自动冷备份，计划包含执行时刻、IANA 时区和保留份数。
到期计划仅在实例处于运行中或已停止状态时原子创建备份与任务；实例正执行其他操作时
保持到期并在恢复稳定后补跑，不抢占或中断生命周期任务。每次成功后按当前策略清理超出
保留份数的计划备份，人工备份永不自动删除。修改或关闭策略后，已排队任务完成时重新读取
当前策略，避免使用过期保留值。自动创建与清理均进入任务中心、审计和 Webhook 链路。

删除必须输入实例名称二次确认。删除容器、Compose 网络、数据卷和平台数据目录，保留
Docker 镜像供其他实例复用。外部路径永不由平台递归删除。

## 8. 模板目录

### 8.1 标准模板

MySQL、MariaDB、PostgreSQL、Redis、Valkey、MongoDB、ClickHouse、Elasticsearch、
OpenSearch、InfluxDB、Neo4j、Cassandra、Microsoft SQL Server、Oracle Database Free、
openGauss。

标准模板提供创建、启停、异常重启、删除、日志、监控、连接信息和同主版本受控升级。

### 8.2 实验模板

TiDB、OceanBase CE、StarRocks、Apache Doris。实验模板在一台主机内运行所需的多个
容器，页面明确标记为开发/测试用途。

### 8.3 明确排除

Greenplum、DB2 z/OS、DB2 IBM i、GaussDB、PolarDB、AnalyticDB、Hologres、
MaxCompute 及其他没有可自由部署容器镜像的云/商业数据源不作为内置模板。

### 8.4 自定义模板包

上传 `.zip`，包含 `dbmock-template.yaml`、`docker-compose.yml`、图标、配置和可选脚本。
模板包定义参数表单、资源要求、连接信息、健康检查、宿主机调优、升级协议和支持架构。
没有升级脚本的自定义模板只能使用镜像重建式同主版本升级。需要备份与回滚的持久化数据必须
绑定到 `{{ .DataPath }}` 下，`spec.image` 必须提供 `/bin/sh` 与 `tar`。

模板采用不可变版本；编辑创建新版本，既有实例保持原版本。被实例引用的模板或镜像
禁止删除。模板包不得覆盖平台生成的 Compose、凭据环境文件、`data/`、`runtime/` 或内部项目
清单；包内路径必须同时兼容 Linux 与默认大小写不敏感的 macOS 文件系统。升级和失败回滚按
版本收敛模板拥有的配置与脚本，只清理上一版本清单中存在而目标版本已移除的文件，不清理
数据或其他运行时文件。

## 9. 镜像与仓库

- 配置多个公有或私有 OCI/Docker Registry，凭据加密保存。
- 支持代理、自签名 CA，并通过 SSH 安装 CA 后重启 Docker（仅用户明确触发）。
- 支持上传 `docker save` 生成的 `.tar` 或 `.tar.gz`。
- 文件分片上传、断点续传、SHA-256 校验、按镜像摘要去重；默认单文件上限 50 GB，
  可在设置中调整。未完成上传保留 7 天，过期分片由服务自动清理。
- 离线镜像集中保存在控制平台，通过可续传的 SSH/SFTP 分发到主机并执行 `docker load`。
- 实例创建和升级均可选择离线镜像；排队或执行中的任务引用期间禁止清理对应归档或仓库。
- 提供未使用镜像扫描和手动清理；不自动删除主机镜像。

## 10. 监控、日志与告警

- 每 30 秒采集主机和实例的 CPU、内存、磁盘、容器状态及健康检查，历史保存 7 天。
- 容器日志轮转：单文件 100 MB，保留 5 个；网页实时查看并下载。
- 默认告警：主机连续 3 次不可达、容器异常退出、容器健康检查失败、连续重启失败、磁盘 80%/90%、
  升级失败、SSH 凭据失效。
- 用户可调整阈值、关闭单项告警和将主机置为维护模式。
- 通用 Webhook 支持多个地址、事件筛选、HMAC 签名、投递记录和手动重投；业务事件失败
  最多重试 5 次，测试请求只发送 1 次。禁用 Webhook 时取消尚未发送的投递，并拒绝测试
  和重投操作。
- 告警确认与解决记录处理账号和时间；自动恢复的告警记录系统处理人，重复处理返回状态冲突。

## 11. 任务中心与审计

创建、删除、运行配置变更、升级、备份/恢复、镜像上传/分发和 Docker 安装/升级均为持久化异步任务。任务展示
状态、阶段、进度、实时日志、耗时和错误；仅在安全阶段允许取消，失败后允许重试。执行失败按 SSH 不可达、
凭据拒绝、主机指纹变化、操作超时、镜像拉取、磁盘不足、Docker 数据路径未共享、端口冲突和健康检查等
稳定故障代码归类。实例页和
任务详情分别展示可理解的原因、对当前操作的影响、恢复建议及默认收起的技术详情；主机相关故障可直接打开
对应主机检查，并保留原任务和受影响资源上下文。主机详情必须区分上下文加载失败、任务与主机不匹配、
主机尚未恢复、主机已就绪、重试执行中、重试成功和再次失败；主机重新检测恢复在线后可在同一处重试
原任务，重试后继续跟踪新任务并返回实例确认状态，不要求用户手工记住任务编号或重新查找实例。上下文
只能由任务和主机 ID 推导，不能接受任意返回地址，也不能绕过任务重试或主机操作权限。只读角色可查看
非敏感故障说明、任务和资源入口，但重试与重新检测仍仅限管理员和运维。稳定故障代码已明确要求先修复
主机时，工作台、实例失败面板、任务列表和任务详情以“检查故障主机”为主操作，并隐藏会重复失败的
直接重试；该导航只依赖任务自身的主机上下文，不因主机名称等辅助数据暂时加载失败而退回危险的直接重试。
实例创建任务在任务列表和详情中必须继续说明当前工作下一步：排队、执行或重试中返回实例部署进度；
成功时管理员和运维直接进入该实例连接信息，只读角色只进入实例状态且明确说明凭据受限；失败、取消或
中断时明确连接信息尚不可交付，并保留标准恢复、重试和实例入口。目标地址只能由受信任的创建任务类型、
资源类型和资源 ID 推导，缺少稳定实例上下文时不生成继续入口。
以备份为资源的任务必须使用任务 payload 中的实例 ID 展示对应实例名称，并从任务列表或详情直接返回
该实例的备份清理上下文；即使实例名称等辅助数据加载失败，仍保留由任务自身推导的安全入口。任务中心
可按实例备份筛选，但不接受客户端提供的任意返回地址；缺少旧任务上下文时只显示备份 ID，不猜测资源关系。
应用重启后恢复排队任务，并把无法继续的运行中任务标记为中断。

审计记录用户、来源 IP、动作、资源、脱敏前后差异、结果、任务和时间。

初始化、登录、工作台、项目、主机、数据库目录、实例列表与详情、镜像与仓库、自定义

## 13. 部署与开源交付

- Apache-2.0 许可证，不收集遥测数据。
- 单个 Go 应用镜像内嵌 React 静态资源；不需要单独前端容器或 Nginx。
- Docker Compose 包含应用和 PostgreSQL 元数据服务。
- 进程级环境变量严格解析；非法时长、数值、公开 URL 或 TLS 密钥对必须阻止启动，
  不能静默使用默认值。公开 URL 只接受无路径、查询参数和片段的 HTTP/HTTPS origin。
- 可信代理配置只接受最多 32 个有效 IP/CIDR，拒绝 IPv4/IPv6 全地址段；未配置或转发链
  非法时使用直接连接方地址。
- 镜像健康检查和控制平面恢复探针必须兼容默认 HTTP、内置 TLS 与反向代理 TLS 终止模式。
- 应用镜像提供 `linux/amd64` 与 `linux/arm64`。
- 控制平台最低配置：2 CPU、4 GB 内存、20 GB 可用磁盘。
- 离线 `.tar.gz` 包含应用镜像、PostgreSQL 镜像、Compose、环境变量示例、安装/升级
  脚本和中英文部署文档；数据库镜像由用户另行上传或从私有仓库拉取。
- 支持将 PostgreSQL 元数据、凭据主密钥和控制端制品一致导出为权限受限的控制平面备份；
  可使用独立口令文件加密。恢复前必须校验归档并自动保存当前状态，失败时回滚；在线和
  离线升级默认先创建控制平面恢复点。
- GitHub Actions 执行单元测试、后端测试、SSH/Docker 模拟集成测试、前端端到端测试、
  多架构构建和安全检查。

## 14. 验收标准

1. 新环境可通过在线或离线 Compose 启动，并在首次访问完成初始化。
2. Linux x86 主机可通过密码或私钥接入、检测资源，并按选择安装 Docker。
3. 可使用一个标准模板及一个自定义模板完整创建、查看连接信息、启停、监控、升级和删除。
4. 离线镜像可以断点上传、校验、分发并用于实例创建。
5. 资源不足、端口冲突、SSH 失效、容器异常和磁盘阈值均能被识别并按配置发送 Webhook。
6. 中英文切换、30 天会话、用户管理、任务恢复、审计检索/导出/清理均可用。
7. `cd backend && go test ./...`、前端类型检查与测试、生产构建和
   `deploy/compose.yaml` 健康检查通过。
8. 可为运行中或已停止的实例创建主机本地冷备份；恢复前校验归档完整性，恢复失败时
   自动回滚，删除备份后主机文件与平台元数据均被清理。
9. 可在容量与模板下限允许时调整实例 CPU、内存、预留磁盘、额外环境变量和自动重启策略；
   运行中实例成功后保持运行，已停止实例保持停止且下次启动应用新配置，失败时自动恢复原
   配置和重启策略，任务历史不泄露环境变量值。
10. 可按实例配置每日或每周自动冷备份、时区和保留份数；实例忙碌时安全延后，计划备份
    成功后只清理超出保留数的计划备份，人工备份不受影响，失败任务和最近状态可追踪。
11. 管理员、运维和只读账号的服务端权限边界有效；只读账号不能修改资源或读取数据库
    密码，运维账号不能管理用户或系统设置，最后一个可用管理员不能被禁用或降级。
12. 可创建并校验包含 PostgreSQL、主密钥和控制端制品的控制平面备份；恢复能覆盖恢复后
    新增的元数据和文件，恢复失败时回到恢复前状态，升级脚本默认先生成可用恢复点。
13. 管理员、运维和只读账号均可维护自己的显示名称和语言偏好；自助修改密码时错误的当前
    密码会被拒绝，成功后当前会话继续有效、其他会话失效，且审计中不出现任何密码内容。
14. 非法部署变量和不匹配的 TLS 证书/私钥会在启动前被拒绝并指出变量名；反向代理终止
    HTTPS 且公开 URL 使用 `https://` 时，会话 Cookie 仍包含 Secure 且响应包含 HSTS。
15. 未配置可信代理时，伪造的 `X-Forwarded-For` 不会进入审计；配置精确代理地址后，合法
    转发链的原始客户端 IP 会进入会话、审计和请求日志，非法或超长转发链安全回退到直连方。
16. 新建实例默认带当前账号负责人和 7 天预计到期时间，可改为常用期限或长期保留；用途、
    负责人和到期时间能在列表、详情和编辑中查看或修改，工作台能进入已到期/即将到期实例，
    且任何提醒都不会自动停删资源。
17. 管理员和运维可从实例列表选择混合状态实例并批量启动、停止或重启；确认页准确说明将执行和
    跳过的数量，服务端最多接受 100 个唯一实例 ID，并逐项返回排队或拒绝结果。部分失败不会
    回滚已创建任务；页面持续跟踪已创建任务到终态，直接展示逐实例失败原因和安全恢复入口，并可重试
    暂时性未排队项；只读账号调用接口被拒绝。
18. 到期队列在一次工作台请求中聚合每个候选的托管备份、活动任务、状态阻断和清理上下文缺口，
    可筛选可复核与有阻断实例；只读账号能查看证据但不能执行决定。队列与实例详情可打开同一
    清理审查；延期 7 天从当前到期日与今天的较晚者计算，长期保留清空到期时间并留下审计。
    永久删除仅在服务端预检就绪后开放精确名称确认，入队事务再次原子检查备份；预检、决定或删除
    失败均可在原处重试。
19. 工作台、任务详情和实例详情中的主机故障入口均携带原失败任务进入正确主机；任务加载失败或
    与主机不匹配时不会开放操作。重新检测成功后可原地重试，页面跟踪新任务到成功或失败并可返回
    实例确认；只读账号只能查看，刷新与窄屏下恢复上下文不丢失且不出现重复主操作。
