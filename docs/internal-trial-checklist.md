# DB Mock 公司内部试用清单

本清单用于首批测试数据库日常部署试用。试用期间只接入明确授权的测试主机，不接入生产主机，
不导入真实业务凭据或数据，也不把 DB Mock 的删除能力用于平台之外已存在的容器和目录。

## 0. 本地先导验证边界

2026-08-02 已使用一次性 Alpine SSH 容器、宿主机 Docker Socket、独立 PostgreSQL 控制平面和合成凭据
走通 PostgreSQL 17 的接入、创建、真实 SQL 登录、日志、停止、启动、SSH 断连、主机重检、任务重试、
健康收敛和连接交付。该证据证明本地真实 SSH / Compose 生命周期可用，但不代表公司网络、防火墙、
授权主机、离线镜像或真实值班权限已经验证；下面的公司试用项仍需逐项执行和签字。

## 1. 部署准备

- [ ] 准备 1 台可回收、已安装 Docker Engine 与 Compose 的 Linux 或 macOS 测试主机，确认 SSH
      账号、主机指纹和网络策略；DB Mock 不代为安装或升级 Docker。
- [ ] 为 DB Mock 配置独立数据根目录和端口池，确认目录中没有需要保留的既有数据。
- [ ] 使用独立的控制平面 PostgreSQL 数据库和主密钥，保存 `deploy/.env` 的安全备份但不提交仓库。
- [ ] 创建管理员、运维和只读试用账号，按真实职责分配角色。
- [ ] 为首批试用项目配置默认环境、使用周期、团队标签、固定模板版本及 CPU/内存/磁盘规格；
      确认不包含密码、固定主机、固定端口或真实公司数据。
- [ ] 选择首批 2～3 个常用数据库模板和版本，确认镜像来源、架构、资源下限及离线可用性；
      将最常用的一组保存为项目部署配置。
- [ ] 配置一个接收测试告警的 Webhook，并确认不会发往生产告警群。
- [ ] 执行控制平面备份，记录恢复命令、归档位置和负责人。

## 2. 首批试用场景

每个场景记录需求收到时间、操作开始/完成时间、页面跳转次数、失败原因、人工补充记录和最终
交付方式。发现问题时保存任务编号、错误代码和脱敏日志，不保存数据库密码。

### 场景 A：标准临时 PostgreSQL

- [ ] 从已配置默认 PostgreSQL 版本与资源的项目卡片发起创建；确认直接进入基础信息，
      页面明确展示已应用的项目约定，返回模板步骤仍可修改。
- [ ] 填写名称后进入资源步骤，确认 CPU、内存和磁盘与项目配置一致，主机仍显示“自动推荐”
      并按当前可承载结果变化；记录相较手工创建减少的模板选择、资源修改和页面往返次数。
- [ ] 停止项目默认模板的新建或删除该版本后再次发起创建；确认安全回到模板选择并提供刷新或
      改选路径，不提交失效引用。恢复模板后确认可继续。
- [ ] 使用只读账号确认能查看项目的非敏感部署配置，但没有创建项目、编辑项目或创建数据库入口。
- [ ] 从工作台进入创建流程，选择 PostgreSQL 固定版本。
- [ ] 使用包含 PostgreSQL、Redis 和 MySQL 的脱敏历史部署数据，确认创建首屏最多展示 3 个常用固定版本，
      按次数和最近使用时间排序；一键选择后仍显示架构、镜像和兼容主机检查。
- [ ] 删除一条试用实例后确认对应版本的历史频次仍保留；禁用该模板版本后确认它不再出现在常用入口。
      使用全新元数据环境确认没有历史时沿用原有搜索选择器，且不出现多余空状态。
- [ ] 首次没有兼容主机时从创建流程接入授权测试主机；能力任务成功后直接继续，确认模板上下文和
      刚接入的目标主机已保留，无需返回目录重新选择。
- [ ] 选择一个只支持 `amd64` 的版本，并只保留 `arm64` 在线主机；确认主机页明确显示所需架构，
      不显示“继续创建数据库”，且直接打开“接入兼容主机”而不会先往返实例页。
- [ ] 在上述接入流程中探测一台 `arm64` 主机；确认检测结果保留、页面说明不兼容原因且保存按钮停用。
- [ ] 模拟刚接入主机离线或进入维护模式，确认页面不会静默沿用，并提供改选或继续接入入口。
- [ ] 填写用途，确认负责人默认当前账号，设置 3 天预计到期。
- [ ] 准备 3 台架构兼容主机，其中 1 台因已有预留无法承载小型资源；进入资源步骤后确认页面直接
      显示“2 / 3 台可承载”、推荐主机和部署后余量，容量紧张主机保持可见但不可选，并明确列出
      CPU、内存或磁盘不足。全程不返回基础信息步骤改选主机。
- [ ] 指定一个超出所有主机端口池的端口，确认页面说明端口约束并禁用下一步；清空端口后在同一步
      恢复自动推荐，再使用推荐主机、端口和小型资源预设完成创建。
- [ ] 在最终确认后、点击创建前让推荐主机离线或占满容量；确认请求未入队时页面明确说明没有创建
      实例或任务、草稿仍保留、错误代码和恢复建议，并刷新部署状态后禁用重复提交。恢复主机后再次
      刷新，确认只有草稿重新满足条件才开放创建；模拟权限拒绝、资源删除和网络结果不确定时仍不
      允许直接重试。模拟同名实例已经存在时确认可打开该实例核对任务。
- [ ] 在项目默认规格为 `2 CPU / 4 GiB / 20 GiB` 时，把单次部署改为 `3 / 6 / 30`，再模拟主机
      状态变化导致创建被拒绝；确认自动刷新和手动“刷新部署状态”后仍显示 `3 / 6 / 30`，不会
      静默恢复项目默认值。返回基础信息时应提示项目规格不同，只有点击“应用默认部署规格”才恢复
      `2 / 4 / 20`。
- [ ] 提交后停留在实例详情，确认部署阶段、进度、下一步和任务记录入口持续可见。
- [ ] 在镜像准备等可取消阶段确认实例详情明确显示下一项平台自动动作；模拟取消接口暂时失败，确认
      页面说明部署仍可能继续并可原地重试。重试接受后确认取消入口消失、页面持续显示等待安全检查点；
      使用只读账号确认能查看相同进度但没有取消入口。
- [ ] 部署执行中从实例详情进入任务记录，确认任务抽屉说明自动刷新、部署完成后的下一步，并能一次
      返回同一实例进度；页面没有要求人工记录任务编号或重新查找实例。
- [ ] 部署成功后从任务抽屉及任务列表直接进入同一实例的连接信息；使用只读账号确认入口降级为
      “查看数据库”并明确凭据受限，不显示连接交付按钮。
- [ ] 部署成功后从“数据库已部署”面板一次进入连接页；在尚未读取凭据时确认项目、环境、用途、
      负责人和预计到期时间正确，揭示后复制包含这些上下文及全部有效连接字段的完整交付摘要并发送给
      试用开发人员。
- [ ] 对一个运行中的常用实例，从实例列表直接打开“快速交付”；确认打开弹窗时尚未读取凭据，
      项目、环境、用途、负责人和预计到期时间可直接核对，明确点击后才写入审计并复制完整摘要，
      且无需进入详情页。对已恢复实例确认摘要包含备份名称、备份时间和恢复验证时间；模拟读取失败后
      在弹窗内重试成功。已停止或异常实例的快捷入口应停用，只读账号不显示该入口。
- [ ] 分别验证 Cassandra、TiDB、StarRocks 和 Doris：创建确认及连接页展示实际认证方式，不出现
      未被数据库使用的密码，URI 与环境变量片段不包含虚假凭据，并持续提示受控网络和防火墙要求。
- [ ] 模拟连接信息接口暂时失败，确认错误持续可见、说明实例运行不受影响，并可在原页重试成功。
- [ ] 使用只读账号确认能看到部署完成和交付受限说明，但没有揭示凭据按钮。
- [ ] 在实例详情分别完成停止、启动和重启；每次提交前确认实例名、当前状态和连接影响，取消后不创建
      任务。使用只读账号确认详情不显示这些操作入口。
- [ ] 在点击重启后模拟实例状态刚发生变化，确认没有创建任务时错误持续可见，明确说明本次请求未改变
      数据库运行状态，并可查看日志、刷新状态；失败留在确认弹窗，关闭后仍有页面级提示。状态重新允许
      后点击重试仍需再次确认，成功排队后错误自动消失并进入标准任务进度。
- [ ] 修改 CPU、内存或环境变量后，在提交运行配置变更的同时让另一条实例任务先入队；确认弹窗保留
      草稿并明确“未排队”和所有运行配置均未改变，展示当前任务入口且禁用重复提交。当前任务结束并
      刷新后才允许使用保留草稿重新确认。
- [ ] 选择同主版本升级目标和镜像来源后模拟控制服务暂时无法入队；确认目标版本与镜像来源仍保留，
      页面明确没有停机、创建升级快照或切换版本/镜像。关闭弹窗后详情页仍有恢复提示，服务恢复后从
      原表单重新确认并进入标准升级任务；权限被拒绝或目标版本失效时不得提供重试。
- [ ] 在工作台确认实例进入即将到期队列。
- [ ] 使用至少 4 个包含“可复核、有备份、活动任务、状态不稳定、缺少用途或负责人”的候选，确认
      工作台无需逐个打开弹窗即可看清证据，并能筛选“可复核”和“有阻断”；只读账号可见证据但无
      清理决定按钮。
- [ ] 在当前筛选中全选至少 4 个候选，批量延期 7 天；确认提交前逐项展示原到期时间与新时间，并明确
      运行状态、数据、备份和连接信息不受影响。模拟一项并发进入删除状态，确认其他项成功、失败项单独
      列出且“只重试失败项”不会再次提交成功项。
- [ ] 批量改为长期保留，确认成功项退出到期队列且每项都有独立审计；使用只读账号确认没有选择框和
      批量决定按钮，直接请求批量清理决定接口返回无权限。确认永久删除没有出现在任何批量入口。
- [ ] 打开清理审查，确认用途、负责人、到期时间、托管备份和活动任务均清楚可见。
- [ ] 先选择延期 7 天，确认到期队列更新且审计记录包含决定；再改回测试所需到期时间。
- [ ] 创建一个手动备份，确认永久删除被阻断并能直接进入备份页；清理引导在删除任务执行中持续可见，
      最后一份备份删除后无需重新寻找入口即可继续服务端审查。
- [ ] 分别在 1440px 和 1024px 页面宽度打开带备份的实例，确认首屏同时看到备份名称、状态和恢复/
      删除入口；查看 SHA-256、创建人等横向元数据时操作列仍固定可见，只读账号不出现写操作。
- [ ] 分别模拟创建、恢复和删除备份在任务入队前因状态冲突与权限被拒绝，确认弹窗持续显示原因、
      影响和恢复建议，关闭后备份页仍保留；刷新后不安全或无权限时没有重试，安全时重新打开原确认，
      且恢复/删除名称必须重新输入。恢复服务后成功入队，旧提示消失并进入任务跟踪。
- [ ] 模拟备份恢复健康检查失败且自动回滚成功，确认实例页和任务详情都明确显示“目标备份未生效”、
      “已恢复操作前数据”和交付前核对要求；管理员/运维可重试，只读账号只能查看任务与日志。
- [ ] 模拟自动回滚未完成，确认实例状态和恢复提示均禁止交付，并要求先保留现场、检查执行记录、
      实例日志与主机回滚快照；不得用绿色运行状态或通用重试文案弱化风险。
- [ ] 从命名备份成功恢复一个运行中实例，确认实例页、恢复任务详情和连接信息页显示相同的备份
      名称、备份时间和健康验证时间；复制交付摘要后确认三项证据随连接地址与凭据一并出现。
- [ ] 在成功恢复后执行一次停止、启动或重启，确认恢复证据仍可查看；只读账号可以核对数据版本
      和进入任务/备份记录，但不能显示或复制明文连接凭据。
- [ ] 分别模拟备份清单和活动任务清单加载失败，确认页面不会把未知证据误判为已具备删除条件，
      重试成功后才开放继续审查。
- [ ] 模拟备份删除任务失败，确认清理引导展示对应备份、原因、影响和恢复建议；普通失败可原地重试，
      SSH 或主机故障进入主机检查，恢复完成后返回同一备份清理上下文。
- [ ] 在任务中心按“实例备份”筛选，确认备份任务显示对应实例名称；从列表资源链接和任务详情的
      “查看实例备份”均返回同一备份清理上下文，实例名称辅助数据加载失败时入口仍可用。
- [ ] 输入实例名称提交安全删除，确认页面直接进入对应任务而非退回列表；模拟一次 SSH 凭据故障，
      确认同一任务给出主机恢复入口。修复并重试成功后，确认回执列出实例名、主机、已释放端口以及
      Compose 项目和托管目录，且不再提供已删除实例的失效链接；只读账号只能查看回执。

### 场景 B：复制一套常用数据库

- [ ] 从已有实例列表直接发起复制部署，确认无需先打开详情；详情中的原入口仍可用。
- [ ] 使用只读账号确认列表和详情均没有复制入口；停用源模板版本后确认列表快捷入口不可用，
      直接访问旧复制地址会安全降级为普通创建。
- [ ] 确认模板版本、资源、用途和非敏感参数已复用。
- [ ] 确认名称、密码、主机和端口未复用，负责人和到期时间使用当前需求的新值。
- [ ] 创建后比较源实例与新实例的任务、连接信息和审计记录。
- [ ] 删除新实例，确认源实例不受影响。

### 场景 C：可恢复的部署失败

- [ ] 在授权测试主机上使用一个可恢复的错误配置制造失败，例如不可写数据目录或已占用端口。
- [ ] 回到工作台，确认待处理事项展示受影响资源、失败操作、可理解原因、目标主机和下一步。
- [ ] 在失败的实例创建任务抽屉确认持续显示“部署未完成，暂不可交付”、连接信息影响和恢复建议，
      并能进入同一实例；修复并重试成功后确认下一步自动切换为连接信息交付。
- [ ] 分别从工作台、任务详情和实例详情点击“检查故障主机”，确认打开正确主机且保留同一个原任务和实例名称。
- [ ] 在任务中心桌面表格和窄屏卡片中确认主机类失败直接显示“检查故障主机”而不是“重试”；普通健康检查等
      无需先修主机的失败仍保留重试。模拟主机辅助信息加载失败，确认恢复入口仍存在。
- [ ] 使用只读账号确认可以查看故障说明、原任务和实例入口，但没有重新检测或重试按钮。
- [ ] 模拟任务读取失败和任务主机不匹配，确认页面持续显示原因且不会开放错误主机上的恢复操作。
- [ ] 修正 SSH 网络、凭据或 Docker 后在恢复面板重新检测；确认主机在线前“重试原任务”不可用，
      检测执行中状态自动刷新，且抽屉中没有第二个重复的“重新检测”按钮。
- [ ] 在同一恢复面板重试原任务，确认 URL 改为新任务、刷新页面仍跟踪新任务，并覆盖再次失败后的原因和重试入口。
- [ ] 在任务中心对一个普通失败任务点击重试，同时让同一实例的备份任务先入队；确认页面明确
      “重试未进入队列”、资源和数据未改变，显示并可打开当前备份任务，且冲突期间重试按钮停用。
      当前任务结束后点击“刷新任务证据”，确认原页开放安全重试；成功后自动打开新任务。
- [ ] 使用同一组失败任务和阻塞任务分别从工作台、实例详情和主机恢复页提交重试；确认三处与任务中心
      展示相同的原因、影响、错误码、当前任务和恢复建议，且不需要跳转后再重新搜索原任务。主机任务的
      影响说明不得误写成实例状态变化。
- [ ] 模拟任务重试请求返回网络错误但服务端已创建任务，确认页面按操作链找到并跟踪新任务；若
      未找到后继任务，确认至少两次证据刷新前不允许再次提交。权限不足、任务不存在或状态变化时
      始终不提供重试。
- [ ] 重试成功后使用“返回实例确认状态”，确认页面明确列出本次恢复操作、成功任务、当前运行状态和
      最近健康时间，并可直接进入本次任务或连接信息；连接页仍保留恢复任务上下文，全程不直接修改
      控制平面数据库。
- [ ] 让重启任务成功时 Docker 健康状态短暂保持 `starting`；确认页面显示“健康状态正在收敛”、
      10 秒自动刷新和手动刷新入口，不显示连接交付入口，也不把这段正常等待写成需要立即排障。状态
      变为运行中后应自动切换为可交付；真正的健康检查失败仍必须保留日志与任务排障入口。
- [ ] 模拟恢复任务清单暂时加载失败，确认页面不推断成功、提供重试和结束确认；重试成功后才显示恢复
      结论。再分别传入不存在、失败或属于其他实例的任务 ID，确认没有连接交付入口。
- [ ] 使用只读账号打开同一恢复确认，确认可以核对操作、任务和当前状态，但没有显示或复制凭据入口。
- [ ] 确认重试排队后旧失败不再重复出现；恢复成功或删除资源后工作台不保留历史噪声。
- [ ] 取消或中断一次创建任务，确认实例恢复面板同时提供“重试任务”“审查清理”和“查看任务”；清理审查直接
      显示用途、负责人、备份与活动任务，不需要再打开“更多操作”。只读账号只能看到失败说明和“查看任务”。
- [ ] 确认失败实例可安全删除，删除任务失败时仍可恢复，释放后的端口可用于后续新实例。

### 场景 D：一批测试数据库的班前启停

- [ ] 对一个运行中实例直接打开列表行内“运行操作”，确认同时提供重启和停止；提交前必须看到实例名、
      当前状态和连接中断影响，取消后不创建任务。对已停止实例确认只提供启动，不开放无效操作。
- [ ] 从列表重启单个实例，确认无需进入详情或勾选批量范围；请求未排队时页面持续显示原因并明确
      数据库状态未因本次请求改变，成功排队后原地跟踪任务，失败时提供主机检查、重试和任务记录入口。
- [ ] 使用只读账号确认列表不显示“运行操作”，直接请求单实例使用的批量生命周期接口仍返回无权限。
- [ ] 在实例列表同时选择运行中、已停止、异常和失败实例，确认页面分别统计可启动、可停止、可重启和会跳过的实例。
- [ ] 发起批量停止，确认提交前明确提示连接会中断，并列出将排队与跳过的数量。
- [ ] 发起批量重启，确认只包含运行中或异常实例，并明确提示现有连接会中断。
- [ ] 确认每个符合条件的实例产生独立任务和审计记录，不符合状态的实例没有变化。
- [ ] 模拟一个实例在确认后状态变化，确认其他实例仍成功排队，未排队项显示可理解原因。
- [ ] 对暂时性失败使用“重试未排队项”，对状态冲突使用“刷新状态”，确认不会重复提交已排队实例。
- [ ] 等待一个已排队任务执行失败，确认实例页原地显示具体实例、原因、影响和恢复建议；主机故障进入带原任务
      上下文的主机恢复，普通失败可以原地重试，成功项不会重复提交。
- [ ] 使用只读账号确认没有选择框和批量按钮，直接请求启动、停止或重启批量接口均返回无权限。

### 场景 E：权限和基本响应式

- [ ] 运维账号可创建、启停、重试、确认到期决定和删除实例，但不能管理用户或系统设置。
- [ ] 只读账号能查看非敏感状态和故障说明，不能查看密码或执行变更。
- [ ] 在桌面和平板宽度检查工作台、实例列表、实例详情、清理审查、编辑弹窗和创建抽屉。
- [ ] 切换中英文，确认关键状态、字段和错误没有遗漏翻译。

## 3. 试用风险与控制

| 风险 | 试用控制 |
| --- | --- |
| 误删仍在使用的测试库 | 必须填写用途、负责人和到期时间；从清理审查核对备份与活动任务，联系负责人后再输入实例名称确认 |
| 端口或资源冲突 | 使用平台推荐值；失败后先看任务恢复建议，不在主机上手工复用平台管理目录 |
| 凭据泄露 | 仅按需揭示；使用交付摘要发送到公司批准的私密渠道；不截图或写入工单正文 |
| 主机或镜像不可用 | 首批只选择已验证主机和固定模板版本；保留备用主机或离线镜像 |
| 变更请求被误认为已入队 | 只以实例页持续显示的任务为准；“未排队”提示明确不代表任务失败，先核对当前任务和刷新状态再重新确认 |
| 项目部署配置过时 | 模板升级或资源基线变化后由运维复核项目配置；模板失效时平台回到模板选择，不固定主机或端口 |
| 批量启停或重启范围错误 | 在提交前核对将排队与跳过的数量及连接中断提示；删除仍逐实例输入名称确认 |
| 批量延期或长期保留范围错误 | 在提交前逐项核对到期变化；失败项只重试失败范围；永久删除不进入批量入口 |
| 控制平面故障 | 每轮试用前备份 PostgreSQL 元数据、主密钥和制品；验证归档校验结果 |
| 历史失败淹没当前问题 | 每个工作日先处理工作台待处理事项；任务中心保留完整历史用于追溯 |
| 到期提醒被忽略 | 每个工作日由值班运维检查工作台到期队列并留下延期、保留或删除决定；DB Mock 不自动停删实例 |
| 任务成功但健康状态尚未收敛 | 只在实例变为运行中后交付连接；健康收敛提示可等待或刷新，超过正常窗口或变为失败后再按日志和任务排障 |

## 4. 回滚与停止试用

出现数据风险、权限越界、无法解释的批量失败或控制平面异常时，立即停止创建和清理操作：

1. 将相关主机设为维护状态，阻止继续调度，但不要手工删除容器或数据目录。
2. 保存任务编号、审计记录和脱敏日志，通知实例负责人确认当前数据库是否仍在使用。
3. 若仅单个操作失败，使用任务页的恢复建议、重试或安全删除流程处理。
4. 若控制平面损坏，停止 DB Mock 服务，按部署文档使用试用前备份执行校验和恢复。
5. 若决定结束试用，逐个确认并删除平台创建的实例，再移除主机连接；最后保留控制平面备份和
   审计导出，停止 Compose 服务。不要用递归命令清理未核对的主机目录。
