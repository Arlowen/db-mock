# DB Mock 公司内部试用清单

本清单用于首批测试数据库日常部署试用。试用期间只接入明确授权的测试主机，不接入生产主机，
不导入真实业务凭据或数据，也不把 DB Mock 的删除能力用于平台之外已存在的容器和目录。

## 1. 部署准备

- [ ] 准备 1 台可回收的 Linux 或 macOS Docker 测试主机，确认 SSH 账号、主机指纹和网络策略。
- [ ] 为 DB Mock 配置独立数据根目录和端口池，确认目录中没有需要保留的既有数据。
- [ ] 使用独立的控制平面 PostgreSQL 数据库和主密钥，保存 `deploy/.env` 的安全备份但不提交仓库。
- [ ] 创建管理员、运维和只读试用账号，按真实职责分配角色。
- [ ] 选择首批 2～3 个常用数据库模板和版本，确认镜像来源、架构、资源下限及离线可用性。
- [ ] 配置一个接收测试告警的 Webhook，并确认不会发往生产告警群。
- [ ] 执行控制平面备份，记录恢复命令、归档位置和负责人。

## 2. 首批试用场景

每个场景记录需求收到时间、操作开始/完成时间、页面跳转次数、失败原因、人工补充记录和最终
交付方式。发现问题时保存任务编号、错误代码和脱敏日志，不保存数据库密码。

### 场景 A：标准临时 PostgreSQL

- [ ] 从工作台进入创建流程，选择 PostgreSQL 固定版本。
- [ ] 填写用途，确认负责人默认当前账号，设置 3 天预计到期。
- [ ] 使用推荐主机、端口和小型资源预设完成创建。
- [ ] 在任务详情确认阶段、进度、下一步和失败恢复入口。
- [ ] 部署成功后揭示凭据，复制完整交付摘要并发送给试用开发人员。
- [ ] 在实例详情完成停止、启动、重启、日志和状态检查。
- [ ] 在工作台确认实例进入即将到期队列。
- [ ] 输入实例名称完成安全删除，并确认容器、数据目录和端口已释放。

### 场景 B：复制一套常用数据库

- [ ] 从已有实例详情发起复制部署。
- [ ] 确认模板版本、资源、用途和非敏感参数已复用。
- [ ] 确认名称、密码、主机和端口未复用，负责人和到期时间使用当前需求的新值。
- [ ] 创建后比较源实例与新实例的任务、连接信息和审计记录。
- [ ] 删除新实例，确认源实例不受影响。

### 场景 C：可恢复的部署失败

- [ ] 在授权测试主机上使用一个可恢复的错误配置制造失败，例如不可写数据目录或已占用端口。
- [ ] 回到工作台，确认待处理事项展示受影响资源、失败操作、可理解原因、目标主机和下一步。
- [ ] 使用只读账号确认可以查看故障说明，但没有重试按钮。
- [ ] 确认页面展示可理解的原因、影响、恢复建议、技术详情和重试入口。
- [ ] 修正主机或创建配置后重试，不直接修改控制平面数据库。
- [ ] 确认重试排队后旧失败不再重复出现；恢复成功或删除资源后工作台不保留历史噪声。
- [ ] 确认失败实例可安全删除，释放后的端口可用于后续新实例。

### 场景 D：权限和基本响应式

- [ ] 运维账号可创建、启停、重试和删除实例，但不能管理用户或系统设置。
- [ ] 只读账号能查看非敏感状态和故障说明，不能查看密码或执行变更。
- [ ] 在桌面和平板宽度检查工作台、实例列表、实例详情、编辑弹窗和创建抽屉。
- [ ] 切换中英文，确认关键状态、字段和错误没有遗漏翻译。

## 3. 试用风险与控制

| 风险 | 试用控制 |
| --- | --- |
| 误删仍在使用的测试库 | 必须填写用途、负责人和到期时间；删除前联系负责人并输入实例名称确认 |
| 端口或资源冲突 | 使用平台推荐值；失败后先看任务恢复建议，不在主机上手工复用平台管理目录 |
| 凭据泄露 | 仅按需揭示；使用交付摘要发送到公司批准的私密渠道；不截图或写入工单正文 |
| 主机或镜像不可用 | 首批只选择已验证主机和固定模板版本；保留备用主机或离线镜像 |
| 控制平面故障 | 每轮试用前备份 PostgreSQL 元数据、主密钥和制品；验证归档校验结果 |
| 历史失败淹没当前问题 | 每个工作日先处理工作台待处理事项；任务中心保留完整历史用于追溯 |
| 到期提醒被忽略 | 每个工作日由值班运维检查工作台到期队列；DB Mock 不自动停删实例 |

## 4. 回滚与停止试用

出现数据风险、权限越界、无法解释的批量失败或控制平面异常时，立即停止创建和清理操作：

1. 将相关主机设为维护状态，阻止继续调度，但不要手工删除容器或数据目录。
2. 保存任务编号、审计记录和脱敏日志，通知实例负责人确认当前数据库是否仍在使用。
3. 若仅单个操作失败，使用任务页的恢复建议、重试或安全删除流程处理。
4. 若控制平面损坏，停止 DB Mock 服务，按部署文档使用试用前备份执行校验和恢复。
5. 若决定结束试用，逐个确认并删除平台创建的实例，再移除主机连接；最后保留控制平面备份和
   审计导出，停止 Compose 服务。不要用递归命令清理未核对的主机目录。
