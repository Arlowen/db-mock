# DB Mock 公司内部试用清单

本清单用于首批测试数据库日常部署试用。试用期间只接入明确授权的测试主机，不接入生产主机，
不导入真实业务凭据或数据，也不把 DB Mock 的删除能力用于平台之外已存在的容器和目录。

## 1. 部署准备

- [ ] 准备 1 台可回收的 Linux 或 macOS Docker 测试主机，确认 SSH 账号、主机指纹和网络策略。
- [ ] 为 DB Mock 配置独立数据根目录和端口池，确认目录中没有需要保留的既有数据。
- [ ] 使用独立的控制平面 PostgreSQL 数据库和主密钥，保存 `deploy/.env` 的安全备份但不提交仓库。
- [ ] 创建管理员、运维和只读试用账号，按真实职责分配角色。
- [ ] 为首批试用项目配置默认环境、使用周期和团队标签；确认不包含密码、主机或真实公司数据。
- [ ] 选择首批 2～3 个常用数据库模板和版本，确认镜像来源、架构、资源下限及离线可用性。
- [ ] 配置一个接收测试告警的 Webhook，并确认不会发往生产告警群。
- [ ] 执行控制平面备份，记录恢复命令、归档位置和负责人。

## 2. 首批试用场景

每个场景记录需求收到时间、操作开始/完成时间、页面跳转次数、失败原因、人工补充记录和最终
交付方式。发现问题时保存任务编号、错误代码和脱敏日志，不保存数据库密码。

### 场景 A：标准临时 PostgreSQL

- [ ] 从工作台进入创建流程，选择 PostgreSQL 固定版本。
- [ ] 首次没有兼容主机时从创建流程接入授权测试主机；能力任务成功后直接继续，确认模板上下文和
      刚接入的目标主机已保留，无需返回目录重新选择。
- [ ] 选择一个只支持 `amd64` 的版本，并只保留 `arm64` 在线主机；确认主机页明确显示所需架构，
      不显示“继续创建数据库”，且直接打开“接入兼容主机”而不会先往返实例页。
- [ ] 在上述接入流程中探测一台 `arm64` 主机；确认检测结果保留、页面说明不兼容原因且保存按钮停用。
- [ ] 模拟刚接入主机离线或进入维护模式，确认页面不会静默沿用，并提供改选或继续接入入口。
- [ ] 填写用途，确认负责人默认当前账号，设置 3 天预计到期。
- [ ] 使用推荐主机、端口和小型资源预设完成创建。
- [ ] 提交后停留在实例详情，确认部署阶段、进度、下一步和任务记录入口持续可见。
- [ ] 部署成功后从“数据库已部署”面板一次进入凭据展示，复制完整交付摘要并发送给试用开发人员。
- [ ] 模拟连接信息接口暂时失败，确认错误持续可见、说明实例运行不受影响，并可在原页重试成功。
- [ ] 使用只读账号确认能看到部署完成和交付受限说明，但没有揭示凭据按钮。
- [ ] 在实例详情完成停止、启动、重启、日志和状态检查。
- [ ] 在点击重启后模拟实例状态刚发生变化，确认没有创建任务时错误持续可见，明确说明本次请求未改变
      数据库运行状态，并可查看日志、刷新状态；状态重新允许后可原地重试，成功排队后错误自动消失。
- [ ] 在工作台确认实例进入即将到期队列。
- [ ] 使用至少 4 个包含“可复核、有备份、活动任务、状态不稳定、缺少用途或负责人”的候选，确认
      工作台无需逐个打开弹窗即可看清证据，并能筛选“可复核”和“有阻断”；只读账号可见证据但无
      清理决定按钮。
- [ ] 打开清理审查，确认用途、负责人、到期时间、托管备份和活动任务均清楚可见。
- [ ] 先选择延期 7 天，确认到期队列更新且审计记录包含决定；再改回测试所需到期时间。
- [ ] 创建一个手动备份，确认永久删除被阻断并能直接进入备份页；清理引导在删除任务执行中持续可见，
      最后一份备份删除后无需重新寻找入口即可继续服务端审查。
- [ ] 模拟备份恢复健康检查失败且自动回滚成功，确认实例页和任务详情都明确显示“目标备份未生效”、
      “已恢复操作前数据”和交付前核对要求；管理员/运维可重试，只读账号只能查看任务与日志。
- [ ] 模拟自动回滚未完成，确认实例状态和恢复提示均禁止交付，并要求先保留现场、检查执行记录、
      实例日志与主机回滚快照；不得用绿色运行状态或通用重试文案弱化风险。
- [ ] 从命名备份成功恢复一个运行中实例，确认实例页、恢复任务详情和连接信息页显示相同的备份
      名称、备份时间和健康验证时间；复制交付摘要后确认三项证据随连接地址与凭据一并出现。
- [ ] 在成功恢复后执行一次停止、启动或重启，确认恢复证据仍可查看；只读账号可以核对数据版本
      和进入任务/备份记录，但不能显示或复制明文连接凭据。
- [ ] 分别模拟备份清单和活动任务清单加载失败，确认页面不会把未知证据误判为已具备删除条件，
      重试成功后才开放继续审查。
- [ ] 模拟备份删除任务失败，确认清理引导展示对应备份、原因、影响和恢复建议；普通失败可原地重试，
      SSH 或主机故障进入主机检查，恢复完成后返回同一备份清理上下文。
- [ ] 在任务中心按“实例备份”筛选，确认备份任务显示对应实例名称；从列表资源链接和任务详情的
      “查看实例备份”均返回同一备份清理上下文，实例名称辅助数据加载失败时入口仍可用。
- [ ] 输入实例名称完成安全删除，并确认容器、数据目录和端口已释放。

### 场景 B：复制一套常用数据库

- [ ] 从已有实例详情发起复制部署。
- [ ] 确认模板版本、资源、用途和非敏感参数已复用。
- [ ] 确认名称、密码、主机和端口未复用，负责人和到期时间使用当前需求的新值。
- [ ] 创建后比较源实例与新实例的任务、连接信息和审计记录。
- [ ] 删除新实例，确认源实例不受影响。

### 场景 C：可恢复的部署失败

- [ ] 在授权测试主机上使用一个可恢复的错误配置制造失败，例如不可写数据目录或已占用端口。
- [ ] 回到工作台，确认待处理事项展示受影响资源、失败操作、可理解原因、目标主机和下一步。
- [ ] 分别从工作台、任务详情和实例详情点击“检查故障主机”，确认打开正确主机且保留同一个原任务和实例名称。
- [ ] 在任务中心桌面表格和窄屏卡片中确认主机类失败直接显示“检查故障主机”而不是“重试”；普通健康检查等
      无需先修主机的失败仍保留重试。模拟主机辅助信息加载失败，确认恢复入口仍存在。
- [ ] 使用只读账号确认可以查看故障说明、原任务和实例入口，但没有重新检测或重试按钮。
- [ ] 模拟任务读取失败和任务主机不匹配，确认页面持续显示原因且不会开放错误主机上的恢复操作。
- [ ] 修正 SSH 网络、凭据或 Docker 后在恢复面板重新检测；确认主机在线前“重试原任务”不可用，
      检测执行中状态自动刷新，且抽屉中没有第二个重复的“重新检测”按钮。
- [ ] 在同一恢复面板重试原任务，确认 URL 改为新任务、刷新页面仍跟踪新任务，并覆盖再次失败后的原因和重试入口。
- [ ] 重试成功后使用“返回实例确认状态”，核对运行状态、健康检查和连接信息；全程不直接修改控制平面数据库。
- [ ] 确认重试排队后旧失败不再重复出现；恢复成功或删除资源后工作台不保留历史噪声。
- [ ] 确认失败实例可安全删除，释放后的端口可用于后续新实例。

### 场景 D：一批测试数据库的班前启停

- [ ] 在实例列表同时选择运行中、已停止、异常和失败实例，确认页面分别统计可启动、可停止、可重启和会跳过的实例。
- [ ] 发起批量停止，确认提交前明确提示连接会中断，并列出将排队与跳过的数量。
- [ ] 发起批量重启，确认只包含运行中或异常实例，并明确提示现有连接会中断。
- [ ] 确认每个符合条件的实例产生独立任务和审计记录，不符合状态的实例没有变化。
- [ ] 模拟一个实例在确认后状态变化，确认其他实例仍成功排队，未排队项显示可理解原因。
- [ ] 对暂时性失败使用“重试未排队项”，对状态冲突使用“刷新状态”，确认不会重复提交已排队实例。
- [ ] 等待一个已排队任务执行失败，确认实例页原地显示具体实例、原因、影响和恢复建议；主机故障进入带原任务
      上下文的主机恢复，普通失败可以原地重试，成功项不会重复提交。
- [ ] 使用只读账号确认没有选择框和批量按钮，直接请求启动、停止或重启批量接口均返回无权限。

### 场景 E：权限和基本响应式

- [ ] 运维账号可创建、启停、重试、确认到期决定和删除实例，但不能管理用户或系统设置。
- [ ] 只读账号能查看非敏感状态和故障说明，不能查看密码或执行变更。
- [ ] 在桌面和平板宽度检查工作台、实例列表、实例详情、清理审查、编辑弹窗和创建抽屉。
- [ ] 切换中英文，确认关键状态、字段和错误没有遗漏翻译。

## 3. 试用风险与控制

| 风险 | 试用控制 |
| --- | --- |
| 误删仍在使用的测试库 | 必须填写用途、负责人和到期时间；从清理审查核对备份与活动任务，联系负责人后再输入实例名称确认 |
| 端口或资源冲突 | 使用平台推荐值；失败后先看任务恢复建议，不在主机上手工复用平台管理目录 |
| 凭据泄露 | 仅按需揭示；使用交付摘要发送到公司批准的私密渠道；不截图或写入工单正文 |
| 主机或镜像不可用 | 首批只选择已验证主机和固定模板版本；保留备用主机或离线镜像 |
| 批量启停或重启范围错误 | 在提交前核对将排队与跳过的数量及连接中断提示；删除仍逐实例输入名称确认 |
| 控制平面故障 | 每轮试用前备份 PostgreSQL 元数据、主密钥和制品；验证归档校验结果 |
| 历史失败淹没当前问题 | 每个工作日先处理工作台待处理事项；任务中心保留完整历史用于追溯 |
| 到期提醒被忽略 | 每个工作日由值班运维检查工作台到期队列并留下延期、保留或删除决定；DB Mock 不自动停删实例 |

## 4. 回滚与停止试用

出现数据风险、权限越界、无法解释的批量失败或控制平面异常时，立即停止创建和清理操作：

1. 将相关主机设为维护状态，阻止继续调度，但不要手工删除容器或数据目录。
2. 保存任务编号、审计记录和脱敏日志，通知实例负责人确认当前数据库是否仍在使用。
3. 若仅单个操作失败，使用任务页的恢复建议、重试或安全删除流程处理。
4. 若控制平面损坏，停止 DB Mock 服务，按部署文档使用试用前备份执行校验和恢复。
5. 若决定结束试用，逐个确认并删除平台创建的实例，再移除主机连接；最后保留控制平面备份和
   审计导出，停止 Compose 服务。不要用递归命令清理未核对的主机目录。
