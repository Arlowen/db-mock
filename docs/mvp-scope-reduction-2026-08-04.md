# DB Mock MVP 范围收缩审计与实施计划

日期：2026-08-04
状态：范围基线、一级入口/工作台收缩和数据库创建/列表收缩已落地，详情页与后端兼容代码尚未删除。

## 1. 结论

DB Mock 的核心部署能力已经存在，当前阻碍不是缺功能，而是默认界面把一个单人测试数据库工具呈现成了企业级控制平台。

当前一级导航有 11 个入口，工作台混入告警、到期治理和批量清理，数据库列表与创建流程还要求理解项目、环境、标签、负责人、到期时间、镜像来源和运行高级选项。它们增加日常操作和维护面，却没有直接缩短“接入主机 → 创建数据库 → 跟踪任务 → 交付连接 → 启停/日志 → 删除”闭环。

本轮采用的收缩策略是：先隐藏用户入口和默认流程，再逐层删除仅服务于非 MVP 的前端与 API；历史表、字段和安全审计写入暂不迁移，避免破坏已有实例或升级兼容性。

### 2.1 核心流程基线

| 环节 | 当前入口和主要操作 | 额外往返或输入 | MVP 判断 |
| --- | --- | --- | --- |
| 初始化/登录 | 首次创建账号后进入工作台 | 页面同时暴露角色和系统管理入口 | 保留初始化、登录、退出、个人密码；隐藏角色治理 |
| 接入主机 | 工作台“接入主机”进入主机弹窗；测试后保存 | 项目、标签、Docker 管理、代理、维护策略等高级信息扩大决策面 | 保留 SSH 与主机能力检测；后续移除自动安装/升级 Docker 入口 |
| 选择模板 | 可先去独立“数据库目录”，也可从数据库创建抽屉选择 | 独立目录造成一次页面往返；实验/自定义模板也进入产品范围 | 模板选择并入“创建数据库”；仅标准内置固定版本可选 |
| 创建数据库 | 5 步：模板、基础信息、资源、选项、确认 | 项目、环境、用途、负责人、到期、标签、私有/离线镜像、额外环境变量等多数不是单人 MVP 必填 | 收缩为模板/版本、名称、主机、资源和必要初始化参数 |
| 跟踪部署 | 创建后进入详情和任务状态，任务中心可查看日志、失败原因和重试证据 | 部分恢复路径跳到被移出 MVP 的备份/镜像页面 | 保留；按任务种类收窄恢复入口 |
| 连接交付 | 数据库列表有快捷交付，详情有连接信息和完整摘要 | 核心能力已具备 | 保留并继续作为验收主路径 |
| 启停/日志 | 列表和详情均有启停/重启；详情含日志、监控、备份 | 监控、备份、升级、在线改配和清理评审挤占核心操作 | 保留启停/重启/最近日志；移出其他标签和更多操作 |
| 删除 | 删除被到期治理、清理评审和备份阻断流程包围 | 用户需要理解非 MVP 生命周期治理 | 回归“输入数据库名称确认”的安全删除；已有备份仍作为底层删除阻断 |

| 任务 | 核心异步任务、阶段/进度/日志、失败原因、资源返回、安全重试、未知结果防重复 | 通用工作流扩张、非 MVP 任务的创建入口 | 历史非 MVP 任务的展示、取消和恢复，避免升级后任务悬空 |

## 4. 问题优先级

### P0

- 暂未发现需要立即删除数据或停用核心部署的 P0。最危险的做法反而是直接删除用户、项目、备份、模板或任务表：这些表被外键、历史实例、恢复逻辑和升级数据库引用。

### P1

- 11 个一级入口与单管理员、单闭环目标严重不匹配。
- 工作台把告警、到期决策和批量清理放在每日入口，掩盖主机、数据库和任务状态。
- 数据库创建要求填写或理解项目、环境、用途、负责人、到期、标签、镜像来源和运行高级选项。
- 数据库详情把监控、备份、复制部署、在线改配、升级和清理评审与核心启停/日志并列。
- 主机页面暴露自动安装/升级 Docker；模板选择暴露实验和自定义模板。
- 单个 E2E 用例耦合全部能力，导致砍一个入口需要同时维护大量无关测试。

### P2

- “实例”“数据库目录”“镜像与仓库”等术语让用户在部署目标与平台资源模型之间切换。
- 顶栏显示管理员角色和告警铃铛，强化了并不存在的团队平台心智。
- 中英文文案和大量非核心空状态持续扩大维护成本。

## 5. 依赖与删除风险

1. `users` 不能直接删除：系统初始化通过有效用户数判断，`sessions`、`tasks.requested_by`、备份和审计都有外键。
2. `projects` 不能先删表：`hosts.project_id`、`instances.project_id` 和部署配置表仍引用项目；第一阶段只停止新流程使用。
3. 实例历史字段不能立即删除：`environment` 是非空枚举；用途、负责人、到期和标签被工作台、清理逻辑与列表筛选读取。
4. 模板记录必须保留：实例外键指向固定版本；实验/自定义模板即使停止新建，也要允许历史实例显示和执行核心生命周期。
5. 备份不能只删页面：已有备份会阻止实例删除，取消/重试和任务恢复还携带 backup ID；必须先定义升级库的兼容行为。
6. 监控、告警和 Webhook 相互耦合：监控产生告警，事件又生成投递；停 worker 前要处理排队投递和旧设置。
7. 批量 API 当前也被列表中的单实例快捷启停复用；删除前必须把单实例动作改回专用 API。
8. 工作台 API 当前聚合告警、用户、项目和到期实例；第一阶段前端忽略这些字段，后续再收窄查询和响应，避免同一提交同时改前后端契约。
9. 审计页面可以删除，但安全审计写入应保留到最后评估；它不应因“单管理员”被误当作无价值安全措施。

## 6. MVP 目标信息架构

```text
工作台
  ├─ 主机可用性
  ├─ 数据库总数 / 异常数
  ├─ 执行中 / 失败任务
  └─ 创建数据库
主机
  ├─ 列表 / 状态 / 不可用原因
  └─ 添加 / 测试 / 编辑 / 删除
数据库
  ├─ 列表 / 状态
  ├─ 创建（内置模板与固定版本在流程内选择）
  └─ 详情（概览 / 连接 / 日志；启停 / 重启 / 删除）
任务
  ├─ 阶段 / 进度 / 日志
  └─ 失败原因 / 返回资源 / 安全重试
个人菜单
  └─ 个人资料 / 修改密码 / 退出
```

## 7. 分阶段删减计划

1. **一级入口和工作台收缩（本轮）**：导航只保留工作台、主机、数据库、任务；移除顶栏告警与角色标签；工作台只保留核心统计、失败事项和创建入口；旧路由和 API 暂留兼容。
2. **数据库主流程收缩（已完成）**：列表和创建流程移除项目/环境/标签/用途/负责人/到期、复制部署、批量选择和高级镜像来源；创建只显示标准内置固定版本与必要配置。单实例启停仍暂时复用批量 API，待后端收缩时替换。
3. **数据库详情收缩**：移除监控、备份、升级、在线改配和清理评审 UI；保留连接、日志、启停/重启和名称确认删除；处理已有备份的明确阻断文案。
4. **主机与模板收缩**：移除 Docker 安装/升级、代理与非必要策略；停用实验/自定义模板新建；删除独立目录和镜像页前端代码。
5. **前端遗留删除与测试拆分**：删除项目、用户、告警、审计、设置、镜像页面及专属组件/文案；把 E2E 拆成初始化、主机、部署、任务、连接、生命周期等核心用例。
6. **后端依赖清理**：在证明无核心和升级依赖后，关闭非 MVP API 与后台 worker，再删除无用服务；不做破坏性历史表迁移。
7. **文档与干净安装验收**：重写 README、需求和架构为 MVP，验证干净主机在线 Compose 安装和完整核心闭环。

## 8. 第一切片验收标准

- 一级侧栏恰好只有“工作台 / 主机 / 数据库 / 任务”四项。
- 独立目录、项目、镜像、告警、审计、用户和设置不再有导航或顶栏入口。
- 工作台不显示告警统计、到期治理或批量清理。
- 工作台显示可用主机、数据库总数/异常数、执行中任务、失败任务和明显的“创建数据库”按钮。
- 数据库列表与详情返回按钮统一使用“数据库”命名。
- 旧页面、API、表和 worker 本轮不删除，已有数据库生命周期不受影响。
- 单元测试、类型检查、构建和真实页面 1440px/1024px 视觉检查通过。

## 9. 第二切片：数据库创建与列表收缩

### 9.1 解决的工作问题

旧创建流程要求单人管理者在部署一个普通测试库时理解并维护项目、环境、用途、负责人、到期时间、标签、端口、绑定地址、凭据、镜像来源和额外环境变量。列表又用项目、环境和生命周期筛选重复呈现这些非 MVP 概念，同时暴露复制部署和批量选择。

后端现有创建服务已能安全推导或生成环境、主机/端口、绑定地址、模板最小资源、用户名、数据库名、密码和自动重启策略，因此前端可以只提交真正的用户决策。

### 9.2 已实现的用户流程

1. “数据库与名称”：只提供标准内置模板/固定版本和部署名称，常用版本按历史部署次数排序。
2. “资源与主机”：使用模板资源预设，允许必要的 CPU/内存/磁盘调整和可选主机，仅显示模板必要初始化参数。
3. “确认”：汇总主机、资源、认证方式、数据库名/用户名和公开镜像；明确密码在创建时生成，提交后直接进入详情并在后台跟踪任务。

列表现仅保留搜索、主机和核心状态筛选，并保留单库启停/重启、快速交付和详情入口。快速交付摘要不再包含项目、环境、用途、负责人和到期时间。

### 9.3 可观察验收证据

- 前端提交体只包含 `name`、`templateVersionId`、`hostId`、`cpu`、`memoryBytes`、`diskBytes` 和 `templateParameters`。
- 实验模板和自定义模板不再出现在新建选项中，但历史实例与表记录未删除。
- 列表不再显示项目/环境/生命周期筛选、环境/生命周期列、复制部署或批量选择框。
- 端到端测试使用真实运行中页面和合理的 PostgreSQL 17/主机/数据库测试数据，验证三步流程、最小提交体、快速交付、单库停止和详情跳转。
- 1440px 与 1024px 列表/创建抽屉/创建后详情视觉抽查未发现悬空按钮、重复标题、遮挡或页面级横向溢出；用例同时断言零控制台错误和零 4xx/5xx 响应。

### 9.4 未消除的风险与下一切片

- 数据库详情仍显示项目、环境、用途、负责人、到期、监控、备份、编辑、升级/改配和清理评审入口，与列表和创建的 MVP 心智尚未完全一致。
- 单实例启停/重启仍调用批量动作 API，该兼容代码在详情收缩并补齐专用动作路径后再删除。
- 下一切片将收缩数据库详情为“概览 / 连接 / 日志”和“启动 / 停止 / 重启 / 名称确认删除”，并为已有备份阻断提供明确文案。
