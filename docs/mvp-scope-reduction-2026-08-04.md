# DB Mock MVP 范围收缩审计与实施计划

日期：2026-08-04
状态：范围基线、一级入口/工作台、数据库创建/列表和数据库详情收缩已落地；主机、前端遗留与后端兼容代码仍待分阶段清理。

## 1. 结论

DB Mock 的核心部署能力已经存在，当前阻碍不是缺功能，而是默认界面把一个单人测试数据库工具呈现成了企业级控制平台。

当前一级导航有 11 个入口，工作台混入告警、到期治理和批量清理，数据库列表与创建流程还要求理解项目、环境、标签、负责人、到期时间、镜像来源和运行高级选项。它们增加日常操作和维护面，却没有直接缩短“接入主机 → 创建数据库 → 跟踪任务 → 交付连接 → 启停/日志 → 删除”闭环。

本轮采用的收缩策略是：先隐藏用户入口和默认流程，再逐层删除仅服务于非 MVP 的前端与 API；历史表、字段和安全审计写入暂不迁移，避免破坏已有实例或升级兼容性。

### 2.1 核心流程基线

| 环节 | 当前入口和主要操作 | 额外往返或输入 | MVP 判断 |
| --- | --- | --- | --- |
| 初始化/登录 | 首次创建账号后进入工作台 | 页面同时暴露角色和系统管理入口 | 保留初始化、登录、退出、个人密码；隐藏角色治理 |
| 接入主机 | 工作台“接入主机”进入主机弹窗；测试后保存 | 项目、标签、Docker 管理、代理、维护策略等高级信息扩大决策面 | 保留 SSH 与主机能力检测；后续移除自动安装/升级 Docker 入口 |
| 选择模板 | 可先去独立“数据库目录”，也可从数据库创建抽屉选择 | 独立目录造成一次页面往返；实验/自定义模板也进入产品范围 | 模板选择并入“创建数据库”；仅标准内置固定版本可选 |
| 创建数据库 | 5 步：模板、基础信息、资源、选项、确认 | 项目、环境、用途、负责人、到期、标签、私有/离线镜像、额外环境变量等多数不是单人 MVP 必填 | 收缩为模板/版本、名称、主机、资源和必要初始化参数 |
| 跟踪部署 | 创建后进入详情和任务状态，任务中心可查看日志、失败原因和重试证据 | 部分恢复路径跳到被移出 MVP 的备份/镜像页面 | 保留；按任务种类收窄恢复入口 |
| 连接交付 | 数据库列表有快捷交付，详情有连接信息和完整摘要 | 核心能力已具备 | 保留并继续作为验收主路径 |
| 启停/日志 | 列表和详情均有启停/重启；详情含日志、监控、备份 | 监控、备份、升级、在线改配和清理评审挤占核心操作 | 保留启停/重启/最近日志；移出其他标签和更多操作 |
| 删除 | 删除被到期治理、清理评审和备份阻断流程包围 | 用户需要理解非 MVP 生命周期治理 | 回归“输入数据库名称确认”的安全删除；已有备份仍作为底层删除阻断 |

## 4. 问题优先级

### P0

- 暂未发现需要立即删除数据或停用核心部署的 P0。最危险的做法反而是直接删除用户、项目、备份、模板或任务表：这些表被外键、历史实例、恢复逻辑和升级数据库引用。

### P1

- 11 个一级入口与单管理员、单闭环目标严重不匹配。
- 工作台把告警、到期决策和批量清理放在每日入口，掩盖主机、数据库和任务状态。
- 数据库创建要求填写或理解项目、环境、用途、负责人、到期、标签、镜像来源和运行高级选项。
- 数据库详情把监控、备份、复制部署、在线改配、升级和清理评审与核心启停/日志并列。
- 主机页面暴露自动安装/升级 Docker；模板选择暴露实验和自定义模板。
- 单个 E2E 用例耦合全部能力，导致砍一个入口需要同时维护大量无关测试。

### P2

- “实例”“数据库目录”“镜像与仓库”等术语让用户在部署目标与平台资源模型之间切换。
- 顶栏显示管理员角色和告警铃铛，强化了并不存在的团队平台心智。
- 中英文文案和大量非核心空状态持续扩大维护成本。

## 5. 依赖与删除风险

1. `users` 不能直接删除：系统初始化通过有效用户数判断，`sessions`、`tasks.requested_by`、备份和审计都有外键。
2. `projects` 不能先删表：`hosts.project_id`、`instances.project_id` 和部署配置表仍引用项目；第一阶段只停止新流程使用。
3. 实例历史字段不能立即删除：`environment` 是非空枚举；用途、负责人、到期和标签被工作台、清理逻辑与列表筛选读取。
4. 模板记录必须保留：实例外键指向固定版本；实验/自定义模板即使停止新建，也要允许历史实例显示和执行核心生命周期。
5. 备份不能只删页面：已有备份会阻止实例删除，取消/重试和任务恢复还携带 backup ID；必须先定义升级库的兼容行为。
6. 监控、告警和 Webhook 相互耦合：监控产生告警，事件又生成投递；停 worker 前要处理排队投递和旧设置。
7. 批量 API 当前也被列表中的单实例快捷启停复用；删除前必须把单实例动作改回专用 API。
8. 工作台 API 当前聚合告警、用户、项目和到期实例；第一阶段前端忽略这些字段，后续再收窄查询和响应，避免同一提交同时改前后端契约。
9. 审计页面可以删除，但安全审计写入应保留到最后评估；它不应因“单管理员”被误当作无价值安全措施。

## 6. MVP 目标信息架构

```text
工作台
  ├─ 主机可用性
  ├─ 数据库总数 / 异常数
  ├─ 执行中 / 失败任务
  └─ 创建数据库
主机
  ├─ 列表 / 状态 / 不可用原因
  └─ 添加 / 测试 / 编辑 / 删除
数据库
  ├─ 列表 / 状态
  ├─ 创建（内置模板与固定版本在流程内选择）
  └─ 详情（概览 / 连接 / 日志；启停 / 重启 / 删除）
任务
  ├─ 阶段 / 进度 / 日志
  └─ 失败原因 / 返回资源 / 安全重试
个人菜单
  └─ 个人资料 / 修改密码 / 退出
```

## 7. 分阶段删减计划

1. **一级入口和工作台收缩（本轮）**：导航只保留工作台、主机、数据库、任务；移除顶栏告警与角色标签；工作台只保留核心统计、失败事项和创建入口；旧路由和 API 暂留兼容。
2. **数据库主流程收缩（已完成）**：列表和创建流程移除项目/环境/标签/用途/负责人/到期、复制部署、批量选择和高级镜像来源；创建只显示标准内置固定版本与必要配置。单实例启停仍暂时复用批量 API，待后端收缩时替换。
3. **数据库详情收缩（已完成）**：移除监控、完整备份管理、升级、在线改配和到期清理评审 UI；保留连接、日志、启停/重启和名称确认删除；已有备份在删除弹窗内逐项安全处理，不形成清理断点。
4. **主机收缩（已完成）**：移除项目、Docker 安装/升级、代理与非必要策略入口；主机接入只保留 SSH、部署位置、能力检测、容量、托管数据库和安全删除。
5. **模板与前端遗留删除（进行中）**：实验/自定义模板已停止出现在新建选项；项目、独立模板目录、镜像、告警、用户、审计和设置页面及其专属前端调用、组件与单测已删除，旧地址已改成兼容跳转。全局旧文案/样式和单文件 E2E 拆分留到下一前端清理切片。
6. **后端依赖清理**：在证明无核心和升级依赖后，关闭非 MVP API 与后台 worker，再删除无用服务；不做破坏性历史表迁移。
7. **文档与干净安装验收（进行中）**：README、需求、架构、在线部署和内部试用清单已重写为单管理员 MVP；离线、自定义模板等旧用户文档已移出。隔离 Compose 项目已从空卷启动、通过健康检查并完成初始化/登录/工作台/退出；仍需在授权测试主机完成真实 SSH/PostgreSQL 闭环验收。

## 8. 第一切片验收标准

- 一级侧栏恰好只有“工作台 / 主机 / 数据库 / 任务”四项。
- 独立目录、项目、镜像、告警、审计、用户和设置不再有导航或顶栏入口。
- 工作台不显示告警统计、到期治理或批量清理。
- 工作台显示可用主机、数据库总数/异常数、执行中任务、失败任务和明显的“创建数据库”按钮。
- 数据库列表与详情返回按钮统一使用“数据库”命名。
- 旧页面、API、表和 worker 本轮不删除，已有数据库生命周期不受影响。
- 单元测试、类型检查、构建和真实页面 1440px/1024px 视觉检查通过。

## 9. 第二切片：数据库创建与列表收缩

### 9.1 解决的工作问题

旧创建流程要求单人管理者在部署一个普通测试库时理解并维护项目、环境、用途、负责人、到期时间、标签、端口、绑定地址、凭据、镜像来源和额外环境变量。列表又用项目、环境和生命周期筛选重复呈现这些非 MVP 概念，同时暴露复制部署和批量选择。

后端现有创建服务已能安全推导或生成环境、主机/端口、绑定地址、模板最小资源、用户名、数据库名、密码和自动重启策略，因此前端可以只提交真正的用户决策。

### 9.2 已实现的用户流程

1. “数据库与名称”：只提供标准内置模板/固定版本和部署名称，常用版本按历史部署次数排序。
2. “资源与主机”：使用模板资源预设，允许必要的 CPU/内存/磁盘调整和可选主机，仅显示模板必要初始化参数。
3. “确认”：汇总主机、资源、认证方式、数据库名/用户名和公开镜像；明确密码在创建时生成，提交后直接进入详情并在后台跟踪任务。

列表现仅保留搜索、主机和核心状态筛选，并保留单库启停/重启、快速交付和详情入口。快速交付摘要不再包含项目、环境、用途、负责人和到期时间。

### 9.3 可观察验收证据

- 前端提交体只包含 `name`、`templateVersionId`、`hostId`、`cpu`、`memoryBytes`、`diskBytes` 和 `templateParameters`。
- 实验模板和自定义模板不再出现在新建选项中，但历史实例与表记录未删除。
- 列表不再显示项目/环境/生命周期筛选、环境/生命周期列、复制部署或批量选择框。
- 端到端测试使用真实运行中页面和合理的 PostgreSQL 17/主机/数据库测试数据，验证三步流程、最小提交体、快速交付、单库停止和详情跳转。
- 1440px 与 1024px 列表/创建抽屉/创建后详情视觉抽查未发现悬空按钮、重复标题、遮挡或页面级横向溢出；用例同时断言零控制台错误和零 4xx/5xx 响应。

### 9.4 未消除的风险与下一切片

- 单实例启停/重启仍调用批量动作 API，该兼容代码在详情收缩并补齐专用动作路径后再删除。
- 列表/创建组件中仍有只服务于旧项目、镜像和批量流程的不可见状态与请求；将在前端遗留删除阶段移除。

## 10. 第三切片：数据库详情与安全删除收缩

### 10.1 解决的工作问题

旧详情页把日常启停、连接交付和日志排障与项目/环境/用途/负责人/到期、监控图表、完整备份管理、编辑、升级和在线改配并列。用户完成一次部署后仍要在五个标签和“更多操作”中寻找下一步；同时如果直接隐藏备份页，历史托管备份又会永久阻断数据库删除。

### 10.2 已实现的用户流程

1. 详情固定为“概览 / 连接信息 / 日志”三个标签；标题直接显示数据库、版本、主机和当前状态。
2. 启动、停止、重启和删除固定在标签栏右侧；启停仍使用提交前影响确认，并保留任务进度、取消、失败原因、安全重试和主机恢复入口。
3. 连接信息保留角色权限、审计提示、单字段复制、完整交付摘要、环境变量、URI 和 JDBC；离开标签后隐藏明文。
4. 日志保留行数、自动刷新、手动刷新、下载、空状态、失败和原地重试。
5. 删除先读取服务端最新审查证据；有活动任务、不可删除状态或托管备份时禁止提交。托管备份可在同一弹窗逐项输入备份名确认删除，任务完成后重新审查，再输入数据库名永久删除。
6. 删除请求响应不确定时清空名称并锁定重复提交，只有刷新服务端状态后才允许重新确认；历史备份任务的资源入口回到数据库概览，不再跳向已移除的备份标签。

### 10.3 可观察验收证据

- 运行时路由只使用新的独立详情页；旧的约 1,000 行详情实现已从列表模块删除。
- 详情加载只请求实例与关联任务；连接、日志、删除审查和备份清单按用户进入相应流程后再请求。
- Playwright 在真实运行的 Go 内嵌页面中完成：列表 → 详情概览 → 连接明文 → 日志 → 备份阻断 → 备份名称确认删除 → 数据库名称确认删除 → 任务中心。
- 用例验证删除与备份删除提交体都使用精确名称，三标签之外不存在监控/备份标签，也不存在编辑/更多操作入口。
- 1440px 与 1024px 的列表、详情、连接、日志、创建后状态以及两层删除弹窗完成视觉抽查；操作按钮边界和页面横向溢出有自动断言，控制台错误与 4xx/5xx 响应均为零。
- `npm run typecheck`、214 个 Vitest 测试、`npm run build` 和 Chromium E2E 通过；底层实例/备份 API、表、任务和审计兼容行为未删除。

### 10.4 未消除的风险与下一切片

- 列表单实例启停仍暂时复用批量 API；详情已使用专用实例动作 API。删除批量兼容代码前需先迁移列表入口。
- 历史备份仍需要在删除流程中逐项处理，这是保留数据安全的有意约束；本切片没有恢复常规备份创建/恢复入口。

## 11. 第四切片：主机接入与日常状态收缩

### 11.1 解决的工作问题

旧主机页把一次 SSH 接入与项目归属、平台代装/升级 Docker、Docker 代理、维护模式和自动重启策略放在同一表单与“更多操作”菜单中。普通列表还每 15 秒读取项目、模板和镜像，即使管理员只想确认主机是否在线。目标主机已经预装 Docker 的 MVP 假设下，这些入口增加误操作风险，也让 Docker 缺失后的恢复路径错误地依赖平台安装能力。

### 11.2 已实现的用户流程

1. 列表只保留名称、在线状态、SSH、Docker/Compose、宽屏容量摘要，以及直接可见的重新检测和编辑；搜索与状态筛选不再包含项目。
2. 接入表单只填写名称、SSH 地址/端口/用户、密码或私钥；数据库访问地址、`/opt/dbmock` 数据目录和 `20000–40000` 端口池使用明确默认值并可按主机规划调整。
3. 保存前一次检测 SSH、系统架构、Docker/Compose、CPU、内存、磁盘、数据目录与端口池；不再要求免密 sudo，也不提供 Docker 安装、升级或代理操作。
4. 详情集中显示当前可用性、最近检测、容量、托管数据库和核心配置。Docker/Compose 缺失时只引导管理员在主机上手工修复后重新检测。
5. 删除前必须成功读取主机关联数据库和任务上下文；有关联数据库、活动任务或证据读取失败时删除保持禁用。删除请求结果不确定时清空名称并锁定重复提交，刷新服务端状态后才允许继续。

### 11.3 底层兼容边界

- 历史 `projectId`、Docker 管理、代理、维护模式、自动重启与标签字段不再由 MVP 表单展示；编辑已有主机时原值会原样回传，避免一次普通连接修改静默覆盖历史数据。
- 对应数据库字段、后端 API、任务 kind 和主机执行代码本切片未删除，旧任务与升级数据仍可读取。新主机明确提交 `manageDocker=false`，不会授权平台安装或升级 Docker。
- 从数据库创建流程进入主机接入时，模板和镜像只为架构连续性按需读取；普通主机列表不再请求项目、模板或镜像。

### 11.4 可观察验收证据

- 单元测试覆盖新主机的非管理默认值，以及编辑已有主机时隐藏兼容字段不被覆盖。
- Chromium 在真实 Go 内嵌页面中完成主机列表、详情、接入、能力检测、最小提交体与数据库完整闭环；提交体不包含用户填写的项目、代理或策略决策。
- 1440px 列表显示容量摘要；1024px 自动省略重复的列表容量列，使重新检测与编辑无需横向滚动。两种宽度的列表、详情抽屉和接入弹窗均无悬空按钮、重复标题、遮挡或页面级横向溢出。
- 详情验证有关联数据库时删除禁用；端到端用例最终断言控制台错误和 4xx/5xx 响应均为零。

### 11.5 未消除的风险与下一切片

- 后端仍接受 Docker 安装/升级/代理动作，以兼容历史任务和旧客户端；关闭这些 API 前需要确认没有核心 worker、恢复路径或升级数据引用。
- 历史维护模式或项目归属仍可能影响调度，但 MVP UI 不再维护这些字段；后端收缩阶段需要设计非破坏性的停用与迁移策略。
- 下一切片将删除已从路由移出的非 MVP 前端页面与专属调用，并把当前单文件核心 E2E 拆成可独立重放的初始化、主机、部署、任务和生命周期用例。

## 12. 第五切片：非 MVP 前端路由与实现删除

### 12.1 解决的工作问题

侧栏虽然已经只有四个入口，但旧的 `/projects`、`/catalog`、`/images`、`/alerts`、`/users`、`/audit` 和 `/settings` 路由仍直接加载完整页面。知道地址的用户仍可进入非 MVP 工作流，前端构建也继续携带这些页面、离线镜像分片上传和专属设置/告警/审计逻辑，造成产品范围与实际运行行为不一致。

### 12.2 已实现的用户流程与兼容边界

1. 项目、模板目录和镜像旧地址统一返回数据库列表，使用户继续从 MVP 创建入口选择内置标准固定版本。
2. 告警、用户、审计和设置旧地址统一返回工作台；未知地址也回到工作台，不显示空白页或已退出能力。
3. 删除七个旧页面，以及只服务这些页面的离线镜像上传、告警/Webhook、审计、监控设置、上传设置和批量到期决策前端代码与单元测试。
4. 后端 API、数据库表、审计写入、历史任务和 worker 本切片均未删除；系统时区仍由只读设置上下文加载，历史实例仍可读取项目、镜像和备份关联数据。

### 12.3 可观察验收标准

- `frontend/src/pages` 只剩首次初始化/登录、工作台、主机、数据库列表、数据库详情和任务六个页面模块。
- 旧地址及其子路径在已登录会话中落到 `/instances` 或 `/dashboard`，核心页标题可见，未知地址同样安全回到工作台。
- 普通构建不再导入七个旧页面，也不再导出浏览器离线镜像分片上传入口。
- 前端类型检查和剩余 44 个 Vitest 文件、192 个测试通过；核心 Chromium 流程继续验证主机、数据库列表/详情/弹窗和两种页面宽度。

### 12.4 未消除的风险与下一切片

- `i18n.ts` 和全局样式仍包含部分不可达旧文案与选择器；它们不再产生页面或 API 入口，但继续增加构建体积。
- 当前 E2E 仍是单个顺序执行的大用例，失败定位和独立重放成本高。
- 下一切片将基于剩余六个页面清理不可达文案/样式，并把 E2E 拆成可独立运行的认证导航、主机和数据库核心场景；随后再进入后端非 MVP API/worker 依赖证明与关闭。
