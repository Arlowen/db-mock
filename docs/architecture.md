# DB Mock MVP 技术架构

更新时间：2026-08-04

## 1. 架构目标

当前架构只为单管理员测试数据库闭环服务：可靠地把浏览器中的最小部署决策转换为目标主机上的
受管 Docker Compose 数据库，并让任务、连接交付、日常启停、日志和安全删除可追踪。

安全性、失败恢复和历史数据兼容继续保留；企业协作、平台扩展和非核心运维能力不定义 MVP 架构。

## 2. 运行拓扑

```text
浏览器
  │ HTTP/HTTPS
  ▼
DB Mock Go 服务
  ├─ 内嵌 React 静态资源
  ├─ 认证、核心 API 与持久化任务 worker
  ├─ 凭据加密与主机/实例编排
  │
  ├──────── PostgreSQL（元数据、会话、任务、加密凭据）
  │
  └─ SSH/SFTP ────── 目标 Docker 主机
                       └─ 每个数据库一个受管 Compose 项目
```

控制平台的 `deploy/compose.yaml` 只有 `dbmock` 和 `postgres` 两个服务。React 构建产物写入
`backend/web/dist`，通过 `go:embed` 随 Go 二进制发布，不需要独立前端容器或 Nginx。

## 3. 技术选型与仓库边界

- 后端：Go 1.25、Chi、pgx。
- 前端：React 19、TypeScript、Vite、Ant Design、React Router、i18next。
- 元数据：PostgreSQL 17。
- 目标编排：SSH/SFTP、Docker Engine、Docker Compose v2。
- 测试：Go test、Vitest、Playwright Chromium。

```text
backend/internal/api/        HTTP 路由、输入输出和服务端授权
backend/internal/auth/       初始化、登录、会话和密码
backend/internal/config/     严格环境变量解析
backend/internal/crypto/     凭据认证加密
backend/internal/hostops/    SSH、主机检测和 Docker 操作
backend/internal/instances/  核心实例生命周期与 Compose 编排
backend/internal/store/      PostgreSQL 事务与查询
backend/internal/tasks/      持久化任务执行、取消、重试和恢复
backend/internal/templates/  代码内置模板及固定版本
frontend/src/pages/          六个运行页面模块
deploy/                      在线 Compose、镜像构建和配置模板
```

## 4. 核心模块与兼容模块

| 模块 | MVP 状态 | 说明 |
| --- | --- | --- |
| 初始化、登录、个人密码 | 核心 | 首个管理员和必要会话安全 |
| 工作台 | 核心 | 主机、数据库、任务与异常摘要 |
| 主机 CRUD 与验证 | 核心 | 只管理预装 Docker/Compose 的 SSH 主机 |
| 内置标准模板读取 | 核心 | 创建时只选择固定的内置标准版本 |
| 实例创建/启停/重启/删除 | 核心 | 持久化任务执行 |
| 连接信息与最近日志 | 核心 | 受保护凭据读取和排障 |
| 任务列表、日志、取消、重试 | 核心 | 只为核心生命周期提供反馈 |
| 项目与用户治理 | 已关闭 | 管理 API 和专属写入已删除；历史表、角色和关联字段保留 |
| 告警、Webhook、审计查询 | 已关闭 | API、通知 dispatcher 和专属查询已删除；安全审计写入保留 |
| 私有仓库、镜像上传、自定义模板、设置写入 | 已关闭 | API 与上传清理 worker 已删除；历史记录只读保留 |
| 备份恢复、升级、改配、到期 | 已关闭 | 历史字段/记录保留；只允许列出并删除阻断实例删除的旧备份 |
| 批量生命周期 | 已关闭 | 列表和详情统一使用单实例 action；批量 API、服务与按 ID 集合查询任务已删除 |
| 主机 Docker 安装、升级与代理 | 已关闭 | 主机只允许探测；历史字段和任务记录保留，但不能再执行或重试 |
| 状态协调器 | 核心 | 周期探测主机并收敛数据库状态，不采样历史指标或发送通知 |
| 备份调度 worker | 已关闭 | 升级后不再按历史策略创建备份 |

后续删除兼容模块时，不允许仅根据“页面已删除”推断后端安全可删。

## 5. 核心数据模型

MVP 直接使用的数据：

- `users`、`sessions`：首个管理员与登录会话。
- `hosts`：SSH、主机指纹、连接地址、数据目录、端口池、能力与状态。
- `templates`、`template_versions`：内置模板和不可变固定版本。
- `instances`：模板版本、主机、资源、端口、期望/实际状态、加密数据库凭据和受管配置。
- `tasks`、`task_logs`：异步操作、阶段、进度、错误、结果、重试链与日志。
- `settings`：当前只对页面返回首次初始化时区；写入 API 已关闭。

历史表与字段继续存在，包括项目、仓库、镜像、备份、备份策略、指标、告警、Webhook、审计和上传记录。
项目、用户治理、仓库、镜像、上传、自定义模板、实例元数据、到期决策、备份创建/恢复/调度、升级、
改配、指标、告警和 Webhook 已经停止新写入；安全审计与历史备份精确删除仍服务核心安全边界。
本阶段不执行删除历史数据的迁移。

所有 ID 使用 UUID，时间以 UTC 存储，页面按初始化时区展示。实例引用不可变模板版本，确保模板
目录继续演进时已有数据库仍能显示和执行核心生命周期。

## 6. 认证与凭据安全

- 初始化事务只允许在尚无有效账号时创建首个管理员。
- 密码使用 Argon2id 哈希；修改自己的密码必须校验当前密码。
- 会话保存在 PostgreSQL，Cookie 使用 HttpOnly、SameSite，HTTPS 下使用 Secure 和 HSTS。
- SSH 和数据库凭据使用 32 字节主密钥的 AES-GCM 密文保存；密文绑定资源上下文。
- 明文数据库凭据只从 `/instances/{id}/connection` 按需读取，不进入实例列表、任务 payload 或日志。
- API 收到无效会话返回 `401`，前端认证上下文立即清空敏感页面状态。
- 可信代理默认关闭；只有直接来源匹配精确 IP/CIDR 时才接受其 `X-Forwarded-For`。

底层仍保留角色字段和授权中间件以兼容已有数据库，但 MVP 只创建和使用首个管理员，不提供角色 UI
或 `/users` 管理 API。个人资料更新使用只能修改昵称和语言的专用存储方法，不能改变用户名、角色、
禁用状态或凭据；密码只经校验当前密码的独立接口修改。`/projects` 管理 API 同样不再注册。

## 7. 主机接入与验证

### 7.1 输入与默认值

前端只收集名称、SSH 地址/端口/用户、密码或私钥、数据库连接地址、数据根目录和端口池。
主机写入协议只接受页面展示的 SSH、连接地址、数据根目录和端口池字段，不再接受项目、Docker
管理、代理、维护、默认重启或标签。新主机由服务端写入安全零值并固定数据库自动恢复默认值；编辑
旧主机时由服务端保留历史字段，但维护/默认重启值不再参与 MVP 部署选址或新实例配置，客户端也不能
借普通连接修改重新开启已退出能力。

### 7.2 服务端验证

`POST /hosts/test` 通过 SSH 执行只读或受控探测：

1. 获取并返回主机密钥指纹。
2. 读取操作系统和 CPU 架构。
3. 验证 Docker Engine 与 `docker compose` 可用。
4. 读取 CPU、内存、磁盘和 Docker 可用资源。
5. 在目标数据根目录创建并删除临时文件，证明 SSH 用户可写。
6. 使用 `ss`、`lsof` 或 `netstat` 探测端口池中的可用端口。

成功后服务端签发约 10 分钟有效的验证令牌，绑定地址、端口、用户、凭据摘要、目录、端口池和
主机指纹。新增或修改关键连接参数必须提交匹配令牌。已接入主机的指纹变化会中止操作。

主机删除在事务内再次检查关联数据库和活动任务，不能只依赖前端按钮状态。

## 8. 模板选择与资源调度

内置模板由 `backend/internal/templates/catalog.go` 随版本发布。模板版本声明：

- 镜像引用和支持架构；
- 默认端口、数据挂载目标和健康检查；
- 最低 CPU、内存、磁盘及可选资源预设；
- 认证方式、用户名、数据库名、URI/JDBC 协议；
- 必要、类型化的初始化参数。

前端 `mvpDatabaseTemplates` 只保留 `builtin && tier === 'standard'` 的模板。实验和自定义记录可供
历史实例解析，但不能新建。

模板 API 只返回 `builtin && tier=standard && selectable` 的版本；实例创建服务也执行同一边界，不能通过
直接请求绕过前端选择实验或历史自定义模板。创建时，服务端根据模板架构、最低资源、主机在线状态、当前预留和端口池重新选择或校验主机。
前端推荐结果只是辅助信息，最终容量和端口冲突检查必须在创建事务内完成。

## 9. 数据库创建与 Compose 布局

### 9.1 最小请求

前端与后端创建请求都只接受：

```json
{
  "name": "orders_test",
  "templateVersionId": "<uuid>",
  "hostId": null,
  "cpu": 1,
  "memoryBytes": 1073741824,
  "diskBytes": 10737418240,
  "templateParameters": {}
}
```

服务端生成数据库密码，按模板推导数据库名、用户名、容器端口和认证方式，并在事务中预留主机、
端口与资源，创建实例和 `instance.create` 任务。数据库写入成功但任务未创建的半完成状态不可见。

JSON 解码使用未知字段拒绝策略；项目、环境、标签、用途、负责人、到期、监听地址、数据库凭据、
额外环境变量、私有仓库和离线镜像字段都会返回 `400`，不能形成隐藏的非 MVP 新配置。

### 9.2 受管目录

每个实例只使用目标主机数据根目录下由 UUID 派生的目录，包含平台生成的 Compose、凭据环境文件、
运行元数据和数据子目录。Compose 项目名也只由实例 UUID 生成。

平台不接受用户提供任意 Compose 路径或删除路径。删除前重新解析并验证目标必须位于已保存主机的
受管数据根目录内；无法证明范围时中止。

### 9.3 健康收敛

创建、启动和重启任务执行 Compose 后不能只以命令退出码判定可交付。worker 持续检查容器存在、
运行状态和模板健康检查，在超时内收敛为运行、失败或异常。连接信息只有在状态允许时交付。

## 10. 持久化任务与请求一致性

核心任务类型为 `instance.create/start/stop/restart/delete` 和 `host.probe`。任务状态至少包含
queued、running、succeeded、failed、canceled、interrupted；阶段与进度使用稳定代码，页面负责中文解释。

- 同一资源同一时刻只允许一个冲突生命周期任务。
- 任务、实例期望状态、资源预留和审计兼容写入在事务中保持一致。
- 正常关机等待 worker 收敛；进程重启后只恢复当前支持的 queued 任务。
- 已退出功能的 queued 任务在启动时按原 payload 回滚预留并终止；其 running 任务转为 interrupted，
  实例保守进入 `failed/stopped`，避免系统猜测远端破坏性操作是否完成。
- 取消只在安全阶段开放，执行器负责恢复受影响状态。
- 重试创建新任务并保留原任务关联，不覆盖失败记录。
- 请求明确失败时返回稳定错误代码；客户端响应不确定时按资源、任务类型、时间和重试链刷新证据。
- 页面没有至少两次成功证据刷新且仍无法证明“未入队”时，不允许再次提交。

任务执行器不把凭据写入阶段消息或 payload；通用错误写入前按 `password`、`token`、`secret`、
`private key` 等稳定标记截断并遮蔽，单条日志限制为 8000 字符。结构化兼容审计另在 store 层递归
遮蔽敏感键。新增错误来源时必须补充脱敏测试，不能假设任意自由文本都会自动识别所有秘密格式。

## 11. 连接、日志和删除

### 11.1 连接信息

连接读取接口从加密实例配置生成实际字段，按模板认证方式省略不适用值。前端可复制单项、环境变量、
URI、JDBC 和完整摘要；明文只保存在当前页面内存，离开连接标签时清除。

### 11.2 最近日志

日志接口通过实例与主机上下文执行受限 `docker compose logs --tail`，tail 值使用允许范围，不拼接
任意 Shell。下载与页面查看使用同一受限来源。

### 11.3 安全删除

删除弹窗先请求 `cleanup-review` 和历史备份列表。虽然备份创建 UI 已移除，历史托管备份仍是数据保护
阻断项；用户可在删除弹窗中逐项精确名称删除，然后重新读取审查证据。数据库删除再次在服务端原子
检查状态、活动任务和备份，输入名称必须精确匹配。

成功删除任务结果保留数据库名、主机、端口和已清理范围，便于数据库记录删除后仍在任务中心交付回执。

## 12. 前端架构

运行页面模块只包含：

- `AuthPages`：初始化与登录；
- `DashboardPage`：MVP 摘要与异常队列；
- `HostsPage`：主机列表、详情与接入；
- `InstancesPage`：数据库列表与三步创建；
- `InstanceDetailPage`：概览、连接、日志和核心操作；
- `TasksPage`：任务列表、详情、日志和恢复。

`AppLayout` 只渲染四个导航项和个人菜单。旧项目、目录、镜像地址跳转到数据库，旧告警、用户、
审计、设置和未知地址跳转到工作台，避免升级后的书签进入空白或遗留功能。

桌面是优先布局；1440px 和 1024px 必须保证主操作可见、弹窗不遮挡、无页面级横向溢出。
中文是 MVP 权威文案；已有英文可保留，但新功能不以双语扩张为交付条件。

## 13. 在线部署与持久化

Compose 命名卷：

- `dbmock_postgres_data`：元数据、会话、任务和密文；
- `dbmock_dbmock_data`：凭据主密钥和兼容制品目录。

`docker compose down` 保留卷；删除卷会永久丢失平台元数据和解密能力。`deploy/.env` 与 TLS 文件
不在命名卷中，必须单独保护且不得提交。

配置在进程启动前严格解析。公开 URL 决定 Cookie/HSTS；内置 TLS 要求匹配证书和私钥；反向代理
部署只信任显式配置的代理 IP/CIDR。

升级脚本在拉取新镜像前调用现有控制平面备份脚本，这是底层数据保护步骤而不是 MVP 管理 UI。
完全离线安装包不属于当前 MVP 文档或验收。

## 14. 后续删除策略

非 MVP 后端收缩必须逐项提供：

1. 核心路由、store、任务 kind、迁移和历史数据引用证据。
2. 新写入已停止的证明。
3. 历史实例和旧任务的兼容读取/终止策略。
4. worker 关闭后的队列与状态处理。
5. API 关闭测试和升级数据库回归。

默认只删除路由、服务和无用依赖；历史表、字段和记录不为“代码干净”做破坏性迁移。

已经关闭的扩展包括镜像/仓库/自定义模板、项目/用户治理、告警/Webhook/指标、主机 Docker 管理与
隐藏策略，以及备份创建恢复、备份调度、数据库升级、在线改配和批量生命周期。历史表和任务记录保持
可读；任务 worker 只领取已注册类型，退出功能的排队任务会安全终止，旧备份仍可在实例删除弹窗内
逐项删除。

## 15. 测试策略

- 前端单元：最小请求、模板过滤、主机最小写协议、状态、故障指导、连接摘要、删除和重试证据。
- 后端单元/集成：认证、主机验证、资源/端口事务、Compose 安全、任务状态机、凭据和迁移。
- Chromium E2E：初始化/登录、旧路由、主机、三步创建、任务、连接、启停、日志、删除阻断和删除。
- 视觉：真实 Go 内嵌页面 1440px 与 1024px 的列表、详情和弹窗，断言零控制台错误和异常 HTTP。
- 部署：Compose 配置校验、健康检查和干净在线环境完整闭环。
- 模板：定期联网验证所交付内置镜像标签与声明架构。
