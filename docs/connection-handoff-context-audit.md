# 连接交付上下文工作流审计

## 工作切片

本轮解决“连接信息可以快速复制，但交付前无法在同一处核对这套数据库为什么存在、交给谁、何时清理”的问题。
范围仅覆盖既有实例和项目数据的展示与交付摘要，不新增数据模型、权限或凭据接口。

可观察验收标准：

1. 从运行中实例列表打开“快速交付”后，不读取凭据也能看到项目、环境、用途、负责人和预计到期时间。
2. 完整连接页在凭据隐藏、读取失败和无凭据权限时仍显示同一组非敏感上下文。
3. 管理员或运维揭示凭据后，复制摘要同时包含交付上下文、实际连接字段和可用的数据版本证据。
4. 缺失项目、用途、负责人或到期时间时显示明确占位，不留空白或猜测值。
5. 只读角色仍不能读取或复制凭据；本轮不改变服务端权限和审计边界。

## 当前流程基线

| 步骤 | 基线操作与跳转 | 健康度 | 观察 |
| --- | --- | --- | --- |
| 1. 找到运行中实例 | 实例列表内完成，0 次页面跳转 | 健康 | 状态和快捷交付入口清楚。 |
| 2. 打开快速交付 | 1 次点击，0 次页面跳转 | 部分健康 | 凭据按需读取，但弹窗只有技术交付说明。 |
| 3. 核对需求上下文 | 关闭弹窗、进入详情并查看概览，至少增加 2 次操作和 1 次页面上下文切换 | 不健康 | 项目、用途、负责人和到期时间不在交付界面。 |
| 4. 复制并发送摘要 | 1 次点击复制，之后人工补充上下文 | 不健康 | “完整摘要”只有连接字段，容易把数据库交给错误对象或遗漏清理期限。 |

重复输入与外部依赖：技术连接字段无需重复输入；但用户必须记忆或人工抄录用途、负责人和到期时间，常见替代方式是
在聊天、工单或个人笔记中再次整理。连接读取失败已有原地重试，因此本轮不改变恢复链路。

## 问题分级

- P0：本轮未发现新的数据破坏、越权或凭据泄漏阻断。凭据仍由服务端权限与审计接口保护。
- P1：交付前必须跨页面核对并手工补充业务与生命周期上下文，增加高频往返，且容易把凭据发给错误使用方或遗漏到期清理。
- P2：界面称为“完整连接摘要”，但未包含已有的用途、负责人和到期信息，信息层级与用户预期不一致。

## 设计决策

保留既有“先核对、后揭示”的交互，在凭据门禁之前增加紧凑的交付上下文区块。快速弹窗和完整连接页复用同一组字段；
复制摘要把这组字段放在运行状态与认证方式之前，使接收者先理解使用边界，再读取连接细节。缺失值复用现有中英文文案，
不引入可编辑表单，避免交付动作悄悄改变实例元数据。

### 保留的优势

1. 快速交付仍为列表内 1 次点击，不增加导航。
2. 明文凭据仍只在明确操作后读取并记录审计。
3. 恢复版本证据、读取失败重试和完整连接页入口保持不变。

### UX 与无障碍风险

1. 增加五个字段后弹窗更高，需在 1440 px 与 1024 px 宽度检查操作按钮、滚动和遮挡。
2. 长用途或负责人可能换行，需验证描述表格不产生横向溢出。
3. 非敏感上下文对只读角色可见，但凭据按钮必须继续由权限控制；需用只读账号验证。
4. 描述区使用现有 Ant Design 语义结构和可读标签，不以颜色单独表达缺失状态。

### 后续机会

如果内部试用证明“交付摘要经常需要不同渠道格式”，再评估可配置的纯文本模板；当前不增加格式编辑器，避免把高频动作
变成维护模板的负担。

## 证据边界

本审计使用隔离 PostgreSQL 控制平面、合成主机/实例/凭据和本机内嵌页面完成，不连接或修改公司真实主机。
真实公司网络、SSH 策略、开发人员接收渠道和凭据治理仍须在内部试用清单中验证。

## 验证结果

- 1440 × 900：实例列表、快速交付读取前/复制成功态、完整连接页凭据隐藏态均通过视觉检查。
- 1024 × 768：中文快速交付、英文快速交付、管理员完整连接页和只读账号完整连接页均通过视觉检查。
- 页面测量：两种宽度的 `documentElement.scrollWidth` 均等于视口宽度；可见弹窗数量为 1，操作按钮均在
  弹窗和视口边界内；“交付上下文”只有一个可见叶子标题。
- 权限：只读账号能看到五项上下文，显示连接信息与复制交付摘要按钮数量均为 0，页面没有密码、URI 或 JDBC 字段。
- 状态：凭据读取前、复制成功、读取失败后重试成功、无权限均有持续可理解反馈；弹窗仍不回显密码或 URI。
- 控制台：最终页面只有 i18next 的信息日志，没有 warning 或 error。
- 自动化：前端类型检查、42 个测试文件中的 187 项单元测试、生产构建和后端 `go test ./...` 通过。
