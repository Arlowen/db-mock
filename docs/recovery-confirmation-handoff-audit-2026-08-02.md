# 主机恢复后实例确认与连接交付审计（2026-08-02）

## 1. 本轮解决的工作问题

主机故障修复并重试成功后，操作者可以从主机抽屉返回实例，但实例页会丢失“刚完成的是哪一次恢复”这一
上下文。重启成功仍展示通用“数据库已部署”提示，任务入口可能指向首次创建记录；操作者必须记住任务、
重新去任务中心查找并人工判断当前状态是否可以交付连接信息。

本轮把主机恢复的新任务作为受信任的确认上下文带回实例详情，在一个页面完成“本次操作已成功 → 当前实例
状态与健康已核对 → 查看本次任务或交付连接信息”。同时修复验证中发现的创建草稿关闭竞态：URL 驱动的
创建意图不会在用户确认放弃后再次打开抽屉。

## 2. 真实页面基线

基线和最终走查均使用隔离 PostgreSQL 控制平面、合成任务和文档专用地址 `192.0.2.40`。没有连接公司
主机、执行 SSH、启动 Compose、修改真实数据库或读取真实凭据。

| 步骤 | 操作次数 / 跳转 | 重复输入 | 基线健康度 | 主要断点 |
| --- | --- | --- | --- | --- |
| 创建任务成功后进入连接页 | 1 / 1 | 无 | 健康 | 可直接进入连接页，凭据按需揭示。 |
| 主机恢复抽屉重试成功后返回实例 | 1 / 1 | 无 | 不健康 | 只回到通用实例概览，恢复任务上下文丢失。 |
| 在实例页确认恢复结果 | 至少 2 / 1 或更多 | 无 | 阻断 | 通用“数据库已部署”文案误导重启场景；需任务中心重新查找正确任务。 |
| 获取连接信息并交付 | 至少 2 / 1 或更多 | 无 | 繁琐 | 必须先凭经验判断当前状态，再切换连接页。 |

### 问题分级

- P0：未发现新的越权、凭据泄露或数据破坏风险；服务端凭据权限、任务重试权限和审计边界仍有效。
- P1：主机恢复成功到实例确认之间丢失新任务 ID，操作者无法证明页面结论对应本次恢复。
- P1：重启等恢复操作错误复用首次部署完成文案和任务入口，容易交付错误任务证据。
- P1：任务记录读取失败或任务不匹配时没有专门的安全降级，容易凭当前绿色状态误判本次恢复成功。
- P2：恢复结果、当前状态、健康时间和下一步分散在任务、主机和实例三个页面。

## 3. 可观察验收标准

1. 主机恢复成功 CTA 携带新任务 ID 返回对应实例，不接受任意返回地址。
2. 实例只认可属于当前实例且状态为成功的精确实例任务；缺失、失败或跨实例任务不得显示成功结论。
3. 成功面板同屏展示本次恢复操作、任务结果、当前实例状态和最近健康时间。
4. 运行中且有凭据权限时可直接显示并交付连接信息，URL 在切换标签后仍保留恢复任务上下文。
5. 任务加载、加载失败、上下文无效、成功、只读限制和结束确认都有独立状态与下一步。
6. 恢复确认存在时不再显示通用首次部署完成面板；查看任务始终打开本次恢复任务。
7. 放弃 URL 驱动的创建草稿后抽屉关闭、创建查询参数移除，且不会竞态重开。
8. 1440px 与 1024px 下没有可见遮挡、悬空操作、重复标题、页面级横向溢出或控制台错误。

## 4. 实现结果

- 新增恢复确认路径和精确任务选择函数，只为有稳定实例资源上下文的任务生成返回路径。
- 主机恢复成功后优先进入 `/instances/:id?recoveryTask=:taskId`，旧资源路径仅作为无实例上下文时的降级。
- 实例详情新增恢复确认面板，覆盖加载、错误、无效、成功和只读状态；成功时复用现有经审计的凭据读取与
  连接交付流程，不新增凭据接口或绕过权限。
- 查看任务固定使用本次恢复任务；结束确认只移除查询参数，不丢失实例页面和当前筛选。
- 恢复上下文存在时隐藏通用部署完成面板，避免把重启误写为首次部署。
- 创建抽屉关闭期间抑制尚未从路由移除的创建意图，待查询参数清除后恢复正常自动打开能力。
- 中英文文案、1024px 两列事实区、窄屏单列布局和既有组件层级保持一致。

## 7. 证据边界与后续风险

- 本轮验证的是控制平面和真实页面，不代表公司网络、SSH、Docker Compose 或数据库进程已验证。
- 合成任务直接进入成功终态以避免任务工作器连接文档专用地址；真实主机恢复与数据库健康收敛时序仍需
  在授权的可丢弃测试主机上按内部试用清单验证。
- `recoveryTask` 是导航上下文而非授权凭据。页面仍从服务端任务清单核对任务归属和终态；服务端 API 权限
  继续限制只读角色和凭据访问。
- 下一轮优先审计内部试用中真实授权主机上的“失败 → 修复 → 重试 → 连接交付”耗时与人工记录点；在获得
  测试主机、凭据和网络授权前不连接公司环境。
